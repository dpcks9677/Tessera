# 6단계 — 기록과 보고

## 기록

5단계 판정이 `PASS` 이거나, 사용자가 `CONCERNS` 를 수락한 뒤에만 진행합니다.

1. 코드를 바꿨으면 `graphify update .` 를 실행해 지식 그래프를 최신화합니다. AST 전용이라 API 비용이 없습니다.
2. `tessera-scribe` 로 계획서를 갱신합니다. 프롬프트에 담을 것: 태스크 ID, 새 상태(`DONE`), 실제 변경 내용, 검증 결과, 0·5단계 게이트 판정(수락한 `CONCERNS` 와 남은 `NOT ASSESSED` 는 `.claude/gates/README.md` 「기록」 형식으로), 오늘 날짜, 다음 작업. 기록 위치(태스크 표·완료 기록·`STATUS.md`·`log.md`)는 scribe가 `docs/plan/process.md` 규칙대로 정합니다.

5단계가 `NOT ASSESSED` 로 끝났으면 상태를 `DONE` 으로 바꾸지 않고, 이유와 필요한 검증만 기록합니다.

## 보고

한국어로 보고합니다.

- 무엇을 바꿨는지 (파일 나열이 아니라 "무엇을 왜")
- 검증 결과와 게이트 판정
- 남은 문제나 후속 작업
- 커밋 제안

**커밋하지 않습니다.** 프로젝트 규칙상 커밋 단위는 마일스톤이고, 매번 사용자 허가가 필요합니다. 태스크 하나가 끝났다고 커밋하지 마십시오. 마일스톤이 끝났다면 `/tessera-gate <대상>` 을 권합니다. 그 스킬이 `.claude/gates/MILESTONE.md` 판정과 커밋 허가 요청을 맡습니다.
