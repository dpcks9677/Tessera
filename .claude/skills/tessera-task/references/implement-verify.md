# 3·4단계 — 구현과 검증

## 3. 구현

`tessera-implementer` 에 확정된 지시서를 넘깁니다. "잘 해봐"가 아니라 파일별 항목 리스트를 줍니다.

대상 파일이 `Assets/02.Scripts/` 아래면 `docs/reference/control_manifest.md` 에서 그 파일이 속한 레이어 절(`## 레이어: …` 줄부터 다음 `## ` 줄 전까지)을 읽어 지시서 끝에 `## 통제 매니페스트` 구간으로 그대로 붙입니다. 여러 레이어에 걸치면 절을 모두 붙입니다. 설계가 「하지 말 것」을 어겨야 한다면 구현으로 넘기지 말고 ADR이 필요한지 사용자에게 묻습니다.

**파일 집합이 겹치지 않을 때만 병렬**로 최대 3개. 하나라도 겹치면 직렬로 돌립니다.

구현 에이전트가 "미해결 지점"을 돌려주면 임의로 무시하지 말고 설계를 다시 봅니다.

## 4. 검증

`tessera-verifier` 를 **단독** 실행합니다.

실패하면 원인을 판정합니다.

- 구현 실수 → 수정 지시서를 만들어 3단계로 되돌립니다.
- 설계 결함 → 2단계로 되돌립니다.
- 환경 문제(Unity 미실행, `currentMode` 가 bypass 아님) → 사용자에게 보고하고 조치를 요청합니다. 5단계에서는 `NOT ASSESSED` 입니다.

**같은 실패로 2회 되돌린 뒤에도 실패하면 중단합니다.** 무한 루프를 돌지 말고 사용자에게 상황을 보고하십시오.

`review_mode` 가 `full` 이면 검증 통과 뒤 `tessera-reviewer` 두 개를 병렬로 띄웁니다. 각각 `.claude/gates/CODE-REVIEW.md`, `.claude/gates/TEST-COVERAGE.md` 를 게이트 파일로 넘기고, 넘길 맥락은 각 게이트 파일의 해당 절을 따릅니다. 판정은 5단계에서 합칩니다. verifier가 도는 동안에는 띄우지 않습니다.
