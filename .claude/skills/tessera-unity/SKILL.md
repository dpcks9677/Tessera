# Unity 작업 오케스트레이션

작업: `$ARGUMENTS`

당신은 오케스트레이터입니다. **설계 판단은 당신이 직접 하고**, Unity 조작은 `tessera-unity-operator` 에 위임합니다.

## 이 플로우의 절대 규칙

**Unity 접근 에이전트는 언제나 하나만 돕니다.** `tessera-unity-operator` 가 실행 중일 때 `tessera-verifier` 를 포함한 어떤 에이전트도 함께 띄우지 마십시오. Unity Editor는 REST 서버 하나에 붙은 단일 인스턴스이고, 동시 조작은 씬을 망가뜨립니다.

조사(`tessera-scout`)와 기록(`tessera-scribe`)은 Unity에 접근하지 않으므로 조작 **전후**에 돌릴 수 있습니다. 조작 **중**에는 돌리지 마십시오. 조작 결과에 따라 다음 단계가 달라지기 때문입니다.

## 절차

### 1. 작업 판독

인자가 태스크 ID(`M17-T18` 등)면 계획서에서 해당 절과 하위 계획서를 찾아 읽습니다. `Grep` 으로 위치를 특정한 뒤 필요한 구간만 읽으십시오.

계획서에 좌표·회전·스케일·색상 수치가 적혀 있으면 **그대로 옮겨 적어 두십시오.** 조작 에이전트에 그 값을 그대로 넘겨야 합니다. 임의로 조정하지 마십시오.

인자가 자유 서술이면 무엇을 어떤 상태로 만들 것인지 한 문장으로 정리하고, 애매하면 사용자에게 확인하십시오.

### 2. 작업 트리 확인

`git status --short` 로 씬과 프리팹에 미커밋 변경이 있는지 봅니다.

이미 씬이 수정돼 있으면 **그 사실을 사용자에게 알리십시오.** 지금 조작이 그 변경과 섞이며, 잘못되면 되돌리기가 어렵습니다. 진행 여부를 확인받으십시오.

### 3. 조사

`tessera-scout` 로 관련 컴포넌트·프리팹 경로·필드 이름을 파악합니다. 프롬프트에 담을 것: 무엇을 조작하려는지, 알아내야 할 대상의 정확한 경로와 타입.

Unity 조작에 필요한 것은 코드 구조가 아니라 **씬 안의 오브젝트 경로와 컴포넌트 필드 이름**입니다. 그걸 물으십시오.

### 4. 조작 순서 확정

**여기서 위임하지 않습니다.** 당신이 판단합니다.

- 어떤 오브젝트를 어떤 순서로 건드릴지, 각 단계의 정확한 파라미터를 확정합니다.
- 되돌리기 어려운 단계(삭제, 프리팹 적용, 씬 저장)를 표시하고, 그 단계가 필요하면 **사용자에게 먼저 허가를 받으십시오.**
- 여러 단계면 `batch` 로 묶을 수 있는지 검토합니다.

다음 경우 멈추고 사용자에게 묻습니다.
- 계획서의 수치와 씬의 현재 값이 크게 다르다
- 지시대로 하면 기존 프리팹 오버라이드가 사라진다
- 삭제나 교체가 필요한데 대상이 다른 곳에서도 참조된다

### 5. 조작

`tessera-unity-operator` 를 **단독** 실행합니다. 확정된 순서와 정확한 값을 프롬프트에 실으십시오. 서브에이전트는 대화 이력을 물려받지 않습니다.

프롬프트에 반드시 포함할 것: 대상 오브젝트 경로, 각 단계의 파라미터 값, 씬을 저장해도 되는지 여부, 확인용 스크린샷이 필요한지.

### 6. 확인

`scene_screenshot` 결과를 실제로 **보십시오.** 파일 경로만 받고 통과시키지 마십시오. 조작 에이전트가 찍은 이미지를 읽어 의도한 상태가 됐는지 판단합니다.

런타임 동작까지 확인해야 하면 `editor_play_capture` 를 쓰되, **씬을 저장한 뒤에만** 호출하십시오. Play Mode 진입·이탈이 저장 안 된 변경을 폐기합니다.

결과가 의도와 다르면 4번으로 돌아갑니다. 같은 문제로 2회 되돌린 뒤에도 어긋나면 중단하고 사용자에게 보고하십시오.

### 7. 기록과 보고

계획서 태스크였다면 `tessera-scribe` 로 상태를 갱신합니다. 이때는 Unity 조작이 끝난 뒤이므로 병렬 제약이 없습니다.

한국어로 보고합니다. 무엇을 어떤 값으로 바꿨는지, 씬을 저장했는지 아니면 dirty 로 남겼는지, 스크린샷으로 확인한 내용, 남은 문제.

**커밋하지 않습니다.** 씬과 프리팹 변경은 특히 커밋 전에 사용자가 직접 눈으로 확인해야 합니다.
