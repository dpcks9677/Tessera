# 플레이테스트 기록

인자: `$ARGUMENTS`

플레이는 사용자가 합니다. 이 스킬은 **관찰을 기록하고 분류**합니다. 관찰에 없는 내용을 지어내지 않습니다.

## 원본

- 폴더·파일 이름 규칙: `docs/qa/README.md`
- 현재 마일스톤과 진행 태스크: 세션 시작 때 주입된 `docs/STATUS.md` 표. 없으면 그 파일을 읽습니다.

## 입력 받기

- `new`: `AskUserQuestion` 으로 묻습니다. 한 번에 최대 4문항이므로 두 번에 나눕니다.
  1. 세션 정보: 플레이어 수, 판 수, 대략의 플레이 시간, 이번에 시험한 것(시험 초점)
  2. 관찰: 좋았던 점, 불편했던 점, 헷갈린 점, 버그로 보이는 것
  각 문항은 「Other」 자유 입력을 받는 것이 기본입니다. 선택지는 흔한 답을 2~4개 제시하는 정도로만 씁니다.
- `analyze <경로|본문>`: 메모를 읽고 양식의 칸에 나눠 담습니다. 메모에 없는 칸은 `기록 없음` 으로 둡니다. 세션 정보가 비면 그 칸만 묻습니다.

환경은 직접 수집합니다. 브랜치·커밋(`git rev-parse --abbrev-ref HEAD`, `git rev-parse --short HEAD`)과 미커밋 변경 유무.

## 분류

관찰 하나하나를 다음 중 하나로 표시합니다.

- **버그** — 규칙이나 표시가 틀림. 「발견한 버그」 절에 모으고, 항목마다 `/tessera-bug-report new` 로 기록할지 마지막에 한 번에 묻습니다.
- **밸런스** — 특정 증강이 너무 강하거나 약하다는 체감. 증강 ID를 확인할 수 있으면 붙이고 `/tessera-balance-check` 대상으로 제안합니다.
- **사용성** — 조작, 정보 표시, 흐름의 불편.
- **연출** — 시각·소리·타이밍.

관찰이 기존 태스크와 겹치는지 확인할 때는 `python .claude/scripts/tessera_query.py tasks --plan <현재 마일스톤 폴더> --state TODO,DOING` 으로 남은 태스크를 보고 ID만 연결합니다.

## 양식

`docs/qa/playtests/YYYY-MM-DD-<슬러그>.md`

```markdown
# 플레이테스트 YYYY-MM-DD — <시험 초점 한 줄>

| 항목 | 값 |
|---|---|
| 날짜 | YYYY-MM-DD |
| 브랜치·커밋 | <branch> · `<short-hash>` (미커밋 변경 있음/없음) |
| 마일스톤 | `Mnn` |
| 플레이어 수 · 판 수 · 시간 | n명 · n판 · 약 n분 |

## 시험 초점
## 흐름
### 좋았던 점
### 불편했던 점
### 헷갈린 점
## 발견한 버그
| 증상 | 심각도 제안 | 기록 |
|---|---|---|
## 증강 체감
| 증강 ID | 체감 | 제안 |
|---|---|---|
## 우선순위 3
1. ...
## 후속 후보
- <태스크 후보와 연결된 기존 태스크 ID, 또는 새 태스크 제안>
```

## 끝내기

1. 파일 경로와 우선순위 3을 보고합니다.
2. 버그 기록과 밸런스 점검을 진행할지 묻습니다. 사용자가 고른 것만 해당 스킬로 넘깁니다.
3. 후속 후보를 계획서 태스크로 옮기는 일은 사용자 확인 뒤 `tessera-scribe` 에 맡깁니다. 자동으로 옮기지 않습니다.

**커밋하지 않습니다.**
