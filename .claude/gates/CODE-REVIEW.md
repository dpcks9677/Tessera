# CODE-REVIEW — 수락 기준·프로젝트 규칙 대조

> 실행 주체: `tessera-reviewer` | 모델 티어: sonnet

**트리거**: `full` 에서 태스크 구현이 끝난 뒤. `lean`·`full` 에서 마일스톤 게이트가 마일스톤 범위 전체로 한 번 부릅니다.

**넘길 맥락**: 대상(변경 파일 목록 또는 커밋 범위), 태스크 ID와 수락 기준(마일스톤 게이트면 README 완료 게이트), 확정한 설계 요약.

## 점검 항목

1. **수락 기준 충족** — 코드가 수락 기준을 실제로 구현합니다. 이름만 맞고 동작이 다른 경우를 찾습니다.
2. **프로젝트 규칙** — 대상 파일에 해당하는 `.claude/rules/` 파일을 읽고 그 기준으로 봅니다. `module-boundary.md`, `serialization.md`, `art-direction.md` 가 주 대상입니다.
3. **범위** — 수락 기준과 무관한 변경, 인접 코드의 임의 개선, 일괄 재포맷이 없습니다.
4. **고아** — 이번 변경으로 미사용이 된 심볼이 남아 있지 않습니다.
5. **정확성** — 근거가 분명한 버그만 적습니다. 범용 리뷰는 `/code-review` 의 몫입니다.

주석이나 ADR에 설계 의도가 명시된 지점은 위반으로 올리지 않습니다.

## 판정

`tessera-reviewer` 심각도와 다음처럼 대응합니다.

- `FAIL`: `치명`·`높음` 지적이 하나라도 있음. 직렬화 데이터 유실 위험, 역방향 의존, 수락 기준 미충족이 여기에 듭니다.
- `CONCERNS`: `중간` 지적만 있음.
- `NOT ASSESSED`: 대상 범위를 특정하지 못함.
- `PASS`: 지적이 없거나 `낮음` 만 있음. `낮음` 지적도 함께 보고합니다.
