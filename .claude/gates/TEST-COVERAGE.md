# TEST-COVERAGE — 테스트 공백 점검

> 실행 주체: `tessera-reviewer` | 모델 티어: sonnet

**트리거**: `full` 에서 태스크 구현이 끝난 뒤. `lean`·`full` 에서 마일스톤 게이트가 마일스톤 범위 전체로 한 번 부릅니다.

**넘길 맥락**: 바뀐 규칙·계산 로직 파일 목록, 추가·수정한 테스트 파일 목록, 태스크 수락 기준.

## 점검 항목

테스트 정책 원본은 `docs/plan/process.md` §7, 테스트 파일 규칙은 `.claude/rules/editor-tests.md` 입니다. 둘 다 읽고 봅니다.

1. **대응 테스트** — 바뀐 규칙·계산 로직마다 그 동작을 검증하는 EditMode 테스트가 있습니다.
2. **사례 구성** — 새 규칙에 정상·경계·거부 사례가 모두 있습니다. 경계는 0, 음수, 빈 배열, 최대 라운드처럼 구체적으로 봅니다.
3. **실제 검증 대상** — 테스트가 바뀐 동작을 보는지, 이름만 비슷하고 다른 것을 보는지 확인합니다.
4. **회귀** — 증강 변경이면 일반 요트 경로를 덮는 테스트가 있습니다.
5. **플레이 모드 항목** — EditMode로 판정할 수 없는 수락 기준을 따로 적습니다.

지적할 때는 "테스트를 추가하라"가 아니라 **어떤 시나리오가 현재 무방비인지**를 씁니다.

## 판정

- `FAIL`: 새 규칙이나 바뀐 계산에 대응 테스트가 하나도 없음.
- `CONCERNS`: 경계·거부 사례가 비었거나, 테스트가 다른 것을 검증함.
- `NOT ASSESSED`: 바뀐 로직의 범위를 특정하지 못함.
- `PASS`: 위 항목을 모두 충족. 5번 플레이 모드 항목은 판정과 별도로 보고합니다.
