# READY — 태스크 준비 점검

> 실행 주체: 주 세션 | 모델 티어: opus

**트리거**: 태스크를 `DOING` 으로 바꾸기 전. `solo` 에서는 생략합니다.

**넘길 맥락**: 태스크 ID, 해당 마일스톤·트랙 `README.md` 의 태스크 행과 완료 게이트, 태스크 문서(있으면), 선행 태스크의 상태.

## 점검 항목

1. **수락 기준** — 태스크 행에 수락 기준이 있고, 테스트나 확인 절차로 판정할 수 있는 문장입니다.
2. **범위** — 손댈 영역(코드 모듈, 씬·프리팹, 문서)이 특정됩니다. Unity 조작이 필요하면 그 사실이 드러납니다.
3. **선행 의존** — 선행 태스크가 `DONE` 입니다.
4. **설계 근거** — 따라야 할 ADR이 `Accepted` 상태입니다. `Proposed` ADR에 기대는 태스크는 확인 대상입니다.
5. **미결 질문** — 태스크 문서나 결정 기록에 열린 질문이 남아 있지 않습니다.
6. **계획과 코드의 일치** — 태스크가 가정하는 심볼·파일이 실제로 있습니다. 위치 확인은 `tessera-scout` 에 맡깁니다.
7. **검증 방법** — EditMode 테스트로 판정할 항목과 플레이 모드 확인이 필요한 항목이 미리 구분됩니다.

## 판정

- `FAIL`: 수락 기준이 없음, 선행 태스크 미완, 계획서와 코드가 어긋남(사용자 확인 전까지 착수하지 않습니다).
- `CONCERNS`: 수락 기준이 모호함, `Proposed` ADR에 의존, 열린 질문이 있으나 착수에 지장은 없음.
- `NOT ASSESSED`: 태스크 문서 링크가 깨졌거나 scout가 위치를 확인하지 못함.
- `PASS`: 위 항목을 모두 충족.
