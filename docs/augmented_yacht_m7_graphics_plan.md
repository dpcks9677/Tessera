# M7. 증강 시스템 그래픽 요소 추가

## 1. 마일스톤 목적

M5에서는 규칙 검증을 위한 최소 표시와 임시 리소스만 사용했다. M7에서는 모든 증강 그래픽을 실제 게임 품질로 완성한다. 그래픽 요소는 규칙 결과를 표현할 뿐 게임 상태를 직접 변경하지 않는다.

아트 작업은 [`art_style_guide.md`](art_style_guide.md)의 스타일라이즈드 중세 판타지 서재/여관 방향, 앰버·인디고 조명 대비, 크림슨·골드 장식 규칙을 따른다.

### M7 완료 조건

- 55개 증강이 카드 또는 상태 표시만 보고 서로 구분된다.
- 특수 주사위의 논리 종류와 화면 외형이 항상 일치한다.
- 증강 발동의 주체, 대상, 결과를 플레이어가 이해할 수 있다.
- 일반 요트 모드에서는 증강 전용 그래픽과 리소스가 생성되지 않는다.
- 그래픽 연출을 생략하거나 중단해도 게임 논리 상태가 달라지지 않는다.
- [`art_style_guide.md`](art_style_guide.md)와 주요 목표 해상도 기준을 통과한다.
- 사용자 결정에 따라 `M7-T10` 사운드·촉각 피드백은 위 완료 조건에서 제외한다.

## 3. 단계별 사용자 협업 규칙

1. 한 번에 하나의 M7 작업만 현재 단계로 지정한다.
2. 현재 단계라도 사용자가 시작 또는 진행을 언급하기 전에는 `TODO`를 유지한다.
3. 사용자가 작업 ID를 명시하면 해당 작업만 `DOING`으로 바꾼다.
4. 작업 완료 후 현재 작업을 `DONE`으로 바꾸되 다음 작업은 자동으로 시작하거나 `DOING`으로 바꾸지 않는다.
5. 완료 결과를 사용자에게 보고한 뒤 사용자가 다음 작업 ID를 언급할 때까지 대기한다.
6. 작업이 차단되면 `BLOCKED`와 필요한 사용자 결정을 기록하고 다른 단계로 임의 이동하지 않는다.
7. `M7-T10`은 `DEFERRED` 상태로 유지한다. `M7-T9` 완료 후 사용자가 지시하면 `M7-T11`로 이동한다.
8. 각 단계에서 사용자와 확정한 내용은 이 문서의 결정 기록과 작업 로그에 남긴다.

## 4. 확정된 시각 사양

### 4.1 카드와 트레이

> 최신 증강 카드 수정 사양과 결과는 [부록 B](#부록-b-증강-카드-디자인-수정-사양)를 우선 기준으로 한다. 보유 카드는 에디터에서 구운 정적 3D 스크롤 프리팹을 사용하고 누락 시에만 안전한 런타임 폴백을 사용한다.

- 카드 스타일은 석재 트레이와 양피지 카드 조합을 사용한다.
- 드래프트 카드 3장은 화면 중앙의 읽기 쉬운 UI로 표시한다.
- 보유 카드는 3D 석재 트레이에 표시하며 플레이어당 최대 3장으로 제한한다.
- 카드에는 이름, 증강별 아이콘, 한 줄 효과, 종류·상태 배지를 표시하고 상세 설명은 호버 시 별도 영역에 표시한다.
- **텍스트 렌더링 파이프라인 (픽셀 필터 우회)**: 증강 카드의 텍스트가 3D 픽셀화 렌더 타겟을 통과하여 깨지는 문제를 방지하기 위해, 점수표(`ParchmentScoreSheet`) 시스템과 동일하게 3D 트레이 슬롯 좌표를 스크린 오버레이(`Pixel Presentation` Canvas)로 투영하여 선명한 고해상도로 렌더링한다.
- **호버 애니메이션 개선**: 호버링 시 픽셀 격자 튐 없이 부드러운 보간(`Lerp`/`SmoothDamp`)을 통해 카드 고도와 스케일(1.0 → 1.06)이 자연스럽게 늘어나고 안착하도록 구현한다.
- **스크롤(두루마리) 디자인 및 테마 다양화**: 펼쳐진 오른쪽 종이는 직사각형 카드로 유지하고, 왼쪽에 철 봉 없는 2.5바퀴 말림·가죽 띠·붉은 인장을 결합한 **양피지 외형 4종**을 구성한다. 얇은 시안 내부선을 사용하며 선택한 외형을 보유 카드와 랜덤 박스 교체 결과까지 유지한다.
- 입력은 호버 강조와 클릭 선택까지만 구현하며 드래그 배치는 후속 작업으로 둔다.
- 공통 양피지 프레임에 증강별 아이콘, 색상, 문양을 조합해 활성 증강 45개를 구분한다.
- 삭제된 6개와 의도적으로 미구현한 4개는 드래프트에 넣지 않고 전용 쇼케이스 씬에서 비활성·미사용 사유와 함께 표시한다.
- M7에서는 시각 시스템을 우선 완성하며 프리팹 굽기와 에디터 배치 저장은 후속 작업으로 분리한다.

### 4.2 랜덤 박스

1. `random-box` 증강 카드를 트레이에 놓는다.
2. 해당 카드 위에서 상자가 열리는 이펙트를 출력한다.
3. 결정된 결과 증강 카드를 기존 카드 위에 겹쳐 표시한다.
4. 교체 연출이 끝나면 최종 보유 카드가 최대 3장인 상태로 정리한다.

### 4.3 점수표와 상태

- 변경된 족보 칸은 작은 증강 문양 스티커 또는 인장으로 표시한다.
- 보너스, 잠금, 진행도, 누적 횟수, 성공·실패는 색상과 상태 배지로 구분한다.
- 수동 증강은 사용 가능, 입력 확인, 성공, 실패 이유를 시각적으로 전달한다.

### 4.4 특수 주사위와 VFX

- `weighted-dice`, `golden-die`, `8-sided`, `promotion-die`, `couple-dice`, `sevens-dice`는 타입별 개별 모델을 사용한다.
- 미구현 `strange-die`는 카드용 고유 아이콘과 비활성 표시만 유지하며 M7에서 주사위 모델을 제작하지 않는다.
- 모델과 시각 규칙은 기존 [`augmented-dice`](https://github.com/dpcks9677/augmented-dice) 프로젝트의 구현을 재사용한다.
- 카드 등장, 획득, 발동, 성공, 실패에는 공통 이벤트 이펙트를 사용하고 증강별 차이는 색상, 아이콘, 문양으로 표현한다.
- 사운드와 햅틱은 구현하지 않고 시각 피드백만 M7 범위에 포함한다.

### 4.5 아이콘 그래픽과 픽셀 보정 파이프라인

- 아이콘은 제시된 레퍼런스의 개별 도안을 복제하지 않고 단색 실루엣, 각진 절단, 네거티브 스페이스, 문장형 구도만 시각 문법으로 사용한다.
- 기본 스타일은 **스타일라이즈드 픽셀 문장 아이콘**으로 확정한다.
- 먼저 해상도 독립적인 문장형 원본을 만든 뒤 자동 픽셀 필터를 적용하고, 작은 크기에서 무너지는 외곽과 내부 빈 공간을 수동 보정한다.
- 제작 순서는 `문장형 원본 → 64×64 자동 픽셀화 → 흑백 임계값·제한 팔레트 적용 → 픽셀 수동 보정 → 32·48·64px 검증 → Unity Point 필터 적용`으로 고정한다.
- 자동 픽셀화 결과를 최종본으로 바로 사용하지 않는다. 고립된 1픽셀, 불규칙한 계단, 소실된 틈, 비대칭을 아이콘별로 정리한다.
- 보정 기준은 최소 선 두께 3px, 최소 내부 간격 3px, 대각선 1:1 또는 1:2 계단, 대칭 도안의 좌우 일치다.
- 원본 아이콘은 단색 알파 마스크로 보관하고 카드용 2~4색 픽셀 버전은 같은 원본에서 파생한다. 상태와 VFX 색상은 Unity 틴트로 재사용한다.
- Unity UI용 픽셀 아이콘은 `Filter Mode: Point`, 밉맵 비활성화를 기본값으로 한다. 월드 공간 재사용본은 거리 앨리어싱을 확인해 별도 임포트 설정을 허용한다.

- 사용자 요청/결정: 선택 창 카드를 기준으로 트레이 카드 UI를 통일하고, 선택 창 카드 본체에도 픽셀 필터를 적용한다. 텍스트 정보 레이어는 기존대로 고해상도를 유지한다.

#### 1. 목적과 판정 기준

이 문서는 원본 증강 55개의 카드, 아이콘, 특수 주사위 외형, 런타임 VFX 필요 여부를 정의한다.

- **카드**: 55개 모두 공통 양피지 카드가 필요하다. 활성 45개는 게임에서 사용하고, 삭제 6개와 미구현 4개는 쇼케이스에서 비활성 사유와 함께 표시한다.
- **아이콘**: 활성 45개와 미구현 4개는 고유 문양을 사용한다. 삭제 6개는 제작 비용을 줄이고 폐기 상태를 즉시 전달하도록 공통 `삭제됨` 문양 하나를 공유한다.
- **주사위**: 활성 규칙에서 전용 주사위 타입을 만드는 6개만 개별 외형이 필요하다. 미구현 `strange-die` 모델은 리워크 확정 뒤로 미룬다.
- **VFX**: 활성 45개는 등장·획득 공통 VFX와 아래 행의 발동 프로필을 사용한다. 삭제·미구현 항목에는 런타임 VFX를 만들지 않고 비활성 카드 오버레이만 사용한다.

#### 3. 공통 제작 단위

##### 카드와 아이콘

- 카드 프레임 1종: 양피지 바탕, 딥 크림슨 테두리, 앤틱 골드 켈틱 트림.
- 상태 오버레이 5종: 선택 가능, 선택됨, 충돌, 사용 완료, 비활성.
- 고유 아이콘 49종: 단색 마스크를 기본으로 하며 카드 강조색과 발동 VFX에서 함께 재사용한다.
- 삭제 공통 아이콘 1종: 삭제된 6개 카드가 함께 사용한다.
- 비활성 사유 배지 2종: `삭제됨`, `미구현`.

##### 아이콘 제작 산출물과 순서

| 순서 | 산출물 | 규격·처리 |
|---:|---|---|
| 1 | 문장형 원본 | 단색 실루엣, 각진 절단, 네거티브 스페이스 중심의 해상도 독립 원본 |
| 2 | 자동 픽셀 초안 | 원본을 64×64px로 래스터화하고 안티앨리어싱 제거·흑백 임계값 적용 |
| 3 | 제한 팔레트 초안 | 단색 마스크 또는 투명색 포함 최대 5색으로 양자화 |
| 4 | 수동 보정본 | 고립된 1픽셀 제거, 최소 선·간격 3px, 대각선 1:1·1:2, 대칭 정리 |
| 5 | 검증본 | 32·48·64px에서 실루엣과 내부 절개 판독 확인 |
| 6 | Unity 임포트 | UI는 Point 필터·밉맵 비활성화, 상태색은 틴트로 적용 |

문장형 원본과 픽셀 보정본을 모두 유지한다. 자동 픽셀 필터는 제작 속도를 높이는 중간 단계이며, 보정 전 결과를 최종 에셋으로 사용하지 않는다.

#### 4. 후속 작업 입력

- `M7-T2`: 카드 공통 레이아웃과 55개 아이콘 슬롯 규격을 이 문서에서 가져간다.
- `M7-T5`: 특수 주사위 6종 표를 모델·머티리얼 제작 체크리스트로 사용한다.
- `M7-T6`: VFX 프로필 열과 공통 프리셋 표를 이벤트 매핑의 시작점으로 사용한다.
- `M7-T11`: 비활성 카드와 누락 아이콘은 공통 물음표 문양으로 안전하게 폴백한다.

#### 5. 확정 결정

1. 삭제된 6개는 전용 아이콘을 만들지 않고 공통 `삭제됨` 문양을 사용한다.
2. 미구현 `strange-die`의 전용 주사위 모델은 M7에서 제작하지 않는다. 카드용 고유 아이콘과 비활성 표시는 유지한다.
3. 아이콘은 레퍼런스의 단색·각진 문장형 시각 문법을 적용하되 개별 도안을 복제하지 않는다.
4. 문장형 원본에 픽셀 필터를 적용하고 64×64px 기준으로 수동 보정한 뒤 32·48·64px에서 검증한다.

#### 6. 아이콘 스타일 검토 결과

- 49개 고유 아이콘에 적용할 공통 그래픽 스타일을 아래 3개 견본으로 비교한 뒤 하나를 확정한다.

| 안 | 스타일 | 핵심 표현 | 장점 | 주의점 |
|---|---|---|---|---|
| 1안 | 손그림 문장형 | 굵은 잉크 외곽선, 2~3개 평면색, 최소 명암 | 48~64px 가독성이 좋고 마스크·VFX 재사용과 49종 대량 제작에 유리함 | 입체감은 세 안 중 가장 낮음 |
| 2안 | 각인 룬석형 | 어두운 슬레이트 부조, 넓은 챔퍼, 금색 홈 | 3D 석재 트레이와 가장 자연스럽게 결합됨 | 작은 카드에서 무겁고 세부 홈이 뭉칠 수 있음 |
| 3안 | 에나멜 보석형 | 크림슨·인디고 에나멜 셀, 골드 금속선 | 마법 유물 같은 고급감과 색상 구분력이 큼 | 49개가 동시에 보이면 시각적 경쟁과 제작 복잡도가 커짐 |

사용자 레퍼런스 검토에 따라 1안의 단순한 실루엣을 더 기하학적으로 정리한 **스타일라이즈드 픽셀 문장 아이콘**을 채택한다. 카드 본체와 트레이가 재질감과 입체감을 담당하므로 아이콘은 단순하고 강한 실루엣을 유지한다. 2안의 석재 질감은 비활성·충돌 상태 배지에 제한적으로 재사용할 수 있다.

#### 7. M7-T2 구현 결과

- 공통 카드 뷰는 스톤 트레이 내부 슬롯(약 4.58×2.58)의 비율인 `1.774:1` 가로형을 사용한다. Full HD UI 기준 카드 크기는 `460×약 259`이다.
- 웹 레퍼런스는 디자인이 아닌 정보 배치만 참고하며, 상단 종류/상태 → 중앙 아이콘 → 이름 → 구분선 → 한 줄 효과 → 하단 대상 순서로 표시한다.
- 드래프트 카드 3장은 화면 중앙에 같은 크기로 가로 배치하며 카드끼리 겹치지 않는다. 선택 모달은 점수표보다 앞에 표시해 모든 카드 내용을 읽을 수 있게 한다.
- 최종 보정 아이콘은 `Assets/Resources/AugmentIcons/{augmentId}`에 Sprite로 배치하면 자동으로 사용한다.
- 최종 아이콘이 아직 없으면 증강 종류별 64×64 임시 픽셀 문양을 사용하며 텍스처 필터는 Point로 고정한다.
- 임시 문양은 공통 레이아웃과 픽셀 파이프라인 검증용이며 49개 고유 아이콘의 최종 도안을 대신하지 않는다.

### 부록 B. 증강 카드 디자인 수정 사양
> 원래 `docs/augmented_yacht_augment_card_design_revision_plan.md`였다. 증강 카드 외형의 기준 사양이다.
#### 1. 목적

증강 선택 창과 스톤 트레이의 보유 카드가 서로 다른 디자인 단계에 머물러 있는 문제를 해소한다. **현재 증강 선택 창의 카드 정보 구조와 가로 비율을 기준 디자인으로 고정**하고, 선택 카드와 보유 카드가 같은 원본 프리셋·안전 영역·상태 표현을 사용하도록 통일한다.

이번 작업은 카드 외형과 표시 계층만 수정한다. 증강 효과, 점수 계산, 드래프트 규칙, 카드 선택 수, 트레이 구조는 변경하지 않는다.

#### 2. 레퍼런스 해석 원칙

두 번째 제공 이미지는 다음 시각 문법만 참고한다.

- 펼쳐진 직사각형 종이와 한쪽의 말린 종이가 한 장처럼 연결되는 구조
- 말린 종이의 겹, 눌린 중앙 실루엣, 가죽 띠와 인장으로 생기는 깊이감
- 오래된 종이의 얕은 찢김과 가장자리 마모
- 종이 본문과 장식 영역의 명확한 분리

이미지의 원본 픽셀, 문양, 텍스트, 손상 위치, 실루엣을 복사하거나 2D 에셋으로 재사용하지 않는다. 모든 메시·텍스처·인장 문양은 Tessera의 스타일에 맞춰 새로 제작한다.

#### 3. 현재 구현 상태와 수정 방향

##### 3.1 확인된 현재 상태

- 선택 창은 `AugmentCardView`와 `AugmentParchmentVisuals.GetSprite`가 만드는 2D 양피지 스프라이트를 사용한다.
- 보유 카드는 `AugmentTrayCardView`가 `AugmentScrollModelFactory`의 정적 3D 프리팹을 배치하고, 동일한 `AugmentCardView`의 정보만 High-Res Overlay로 투영한다.
- 따라서 이름·설명·상태 정보는 일부 공유하지만, 종이 외곽과 말림은 서로 다른 생성 경로를 사용한다.
- 현재 프리셋은 5종이며 외곽 굴곡이 커서 카드가 직사각형보다 물결 모양 양피지로 읽힌다.
- 현재 3D 말림은 별도 롤 메시로 구성되어 있으나 게임 카메라에서 얇은 막대처럼 뭉쳐 보이는 문제가 기록되어 있다.
- 카드 프리셋 ID는 드래프트 선택값에서 보유 카드와 랜덤 박스 결과까지 전달된다.

##### 3.2 통일 원칙

선택 창 카드를 기준으로 다음 하나의 시각 사양을 사용한다.

```text
공통 카드 프리셋 4종
├─ 선택 창: 동일 3D 원본의 정면 베이크 스프라이트 + 공통 정보 UI
└─ 스톤 트레이: 동일 3D 프리팹 + 공통 정보 UI 오버레이
```

- 메시 생성 규칙, 종이 재질, 말림, 띠, 인장, 내부 테두리, 안전 영역은 한 곳에서 정의한다.
- 선택 창에서는 런타임 3D 카메라를 추가하지 않고, 에디터에서 같은 프리팹을 정면 렌더한 투명 스프라이트를 사용한다.
- 트레이에서는 같은 프리팹을 현재 슬롯 앵커에 배치한다.
- 정보 UI는 두 화면 모두 `AugmentCardView`를 유지하되 동일한 정규화 안전 영역을 적용한다.

#### 4. 확정 디자인 사양

##### 4.1 카드 본체

- 전체 점유 영역은 기존 가로형 비율 `1.774:1`을 유지하되, 직사각형 카드 외형은 오른쪽의 펼쳐진 본문에만 적용한다.
- 기존 상·하단의 큰 물결과 삐뚤삐뚤한 금색 아웃라인을 제거한다.
- 펼쳐진 종이 본체는 평평한 직사각형을 기본으로 하고, 외곽 알파/메시에는 작은 찢김과 섬유 빠짐만 넣는다. 왼쪽 말림 뒤에는 직사각형 종이 판을 깔지 않는다.
- 찢김은 카드 전체 폭·높이의 약 `0.5~1.5%` 범위로 제한해 멀리서 직사각형으로 읽히게 한다.
- 네 모서리와 가장자리의 찢김 위치만 다르게 한 **4종 종이 프리셋**을 제작한다.
- 종이 질감은 따뜻한 양피지색, 넓고 낮은 대비의 얼룩, 약한 섬유 결만 사용한다. 반복되는 실사 노이즈와 강한 PBR 요철은 사용하지 않는다.

##### 4.2 내부 테두리

- 종이 가장자리 안쪽에 한 줄의 얇은 테두리를 둔다.
- 기준색은 태서렉트의 시안 계열을 낮은 강도로 변형한 `#5EDCFF` 전후로 하고, 과노출되지 않는 약한 발광을 사용한다.
- 선 두께는 선택 창 기준 `1~2 px`, 트레이의 `640×360` 내부 렌더 기준 최소 `1 px`이 남도록 조정한다.
- 외곽 찢김을 따라 흔들리지 않고, 직사각형 정보 영역을 안정적으로 감싸는 선으로 제작한다.
- 선택·충돌·사용 완료 상태는 기존 상태색을 유지하되 내부 시안 선 자체의 정체성을 덮지 않도록 밝기와 알파만 보조 조정한다.

##### 4.3 왼쪽 말림 장식

- 말린 부분은 카드 왼쪽에 세로축으로 배치하고 펼쳐진 본체의 왼쪽 경계와 이음매 없이 연결한다. 말림의 위·아래 끝은 펼쳐진 직사각형보다 약간 돌출되고 불규칙하게 퍼진다.
- 봉 또는 금속 축은 구현하지 않는다.
- 단면에서 약 `2.5바퀴`의 종이층이 식별되어야 한다.
- 완전한 원통 대신 위·아래가 조금 넓고 중앙이 안으로 들어간 실패형 실루엣으로 만든다. 절차형 메시 또는 변형한 실린더 메시를 사용할 수 있다.
- 말림 폭·높이·겹 간격은 실제 비율보다 과장하되, 별도의 `Pixel Readable Roll Layers` 보조 메시는 사용하지 않고 2.5바퀴 말림 본체만으로 표현한다.
- 겹 안쪽은 종이 앞면보다 어둡게 하고, 밝은 외곽 림과 접촉 그림자를 분리해 픽셀 필터 후에도 말림이 읽히게 한다.
- 미세 섬유로 말림을 설명하지 않고 큰 실루엣, 단계형 명암, 겹 간 간격으로 표현한다.

##### 4.4 가죽 띠와 붉은 인장

- 말림 중앙의 들어간 부분을 짙은 갈색 가죽 띠가 한 바퀴 감싼다.
- 띠는 종이와 명도·색상 차이가 충분해야 하며 별도 리본 꼬리는 만들지 않는다.
- 띠 위에 딥 크림슨 계열의 붉은 밀랍 인장을 배치한다.
- 인장 중앙 문양은 Tessera를 상징하는 **정육면체** 양각으로 새로 제작한다.
- 원거리 가독성을 위해 인장과 정육면체 문양은 실제 비율보다 크게 만들고, 문양은 미세한 선각 대신 면이 분명한 저해상도 실루엣을 사용한다.
- 기존 원형 인장 상태 틴트는 유지하되 선택 상태가 정육면체 문양을 지우지 않도록 별도 머티리얼 프로퍼티로 색만 변경한다.

##### 4.5 정보 안전 영역

- 말림·띠·인장은 장식 전용 영역으로 지정하며 텍스트와 아이콘을 출력하지 않는다.
- 카드 왼쪽 약 `20~24%`를 장식 거터로 예약한다.
- 이름, 종류, 상태, 아이콘, 한 줄 효과, 대상 표시는 나머지 오른쪽 `76~80%` 안에서 기존 선택 창의 계층을 유지한다.
- `AugmentCardView`에 공통 `Content Root`를 두고 선택 창과 트레이 오버레이가 같은 앵커·여백을 사용하게 한다.
- 트레이 오버레이 앵커도 이 안전 영역의 네 모서리에 맞춰 갱신한다.

#### 5. 4종 프리셋 구성

네 프리셋은 카드 크기, 말림 크기, 띠·인장 위치, 내부 테두리, 정보 안전 영역을 공유한다. 차이는 종이 외곽의 작은 손상 패턴에만 둔다.

| ID | 프리셋 | 차이 |
|---|---|---|
| 0 | 기본 마모 | 우상단과 좌하단에 짧고 얕은 섬유 빠짐 |
| 1 | 상단 찢김 | 상단 2곳의 작은 V자 찢김과 우측 가장자리 마모 |
| 2 | 하단 찢김 | 하단 2곳의 비대칭 찢김과 좌측 연결부의 눌림 |
| 3 | 모서리 마모 | 우상단·우하단 모서리의 둥근 마모와 짧은 균열 |

- 손상은 정보 안전 영역과 내부 테두리를 끊지 않는다.
- 3장의 드래프트 선택지에는 가능한 한 서로 다른 프리셋을 배정한다.
- 기존 저장/진행 상태의 프리셋 `4`는 프리셋 `3`으로 변환해 카드 외형만 안전하게 이관한다.

9. 프리셋 배정 범위를 4종으로 변경하고 기존 ID `4` 이관을 적용한다.
10. 선택 창 → 선택 완료 → 트레이 표시 → 랜덤 박스 교체의 외형 연속성을 회귀 검증한다.

#### 8. 테스트 및 완료 기준

##### 8.1 자동 검증

- 프리셋 개수와 정규화: `0~3` 유지, 기존 `4 → 3`, 그 외 잘못된 값 `→ 0`.
- 드래프트 3장에 중복 없는 프리셋이 배정된다.
- 선택한 프리셋 ID가 보유 카드와 랜덤 박스 교체 결과까지 유지된다.
- 프리팹 4종과 대응 프리뷰 스프라이트 4종이 모두 로드된다.
- 각 프리팹에 본체, 말림, 가죽 띠, 인장, 내부 테두리, 안전 영역 앵커가 존재한다.
- 말림 메시의 회전량이 약 2.5바퀴이며 중앙 반경이 양끝보다 작다.
- 인장에 정육면체 문양 메시가 존재하고 봉·리본 꼬리 오브젝트는 존재하지 않는다.
- 선택 창과 트레이 카드의 정보 요소가 같은 정규화 안전 영역을 사용한다.
- 일반 요트 모드에서는 증강 카드 프리팹과 오버레이가 생성되지 않는다.

##### 8.2 시각 검수

- 선택 창과 트레이 카드가 같은 프리셋으로 즉시 식별된다.
- 카드 본체는 첫인상에서 직사각형이고, 가까이서만 4종의 찢김 차이가 보인다.
- 기존의 굵은 금색·물결형 외곽선이 보이지 않는다.
- 내부 시안 선은 얇고 은은하며 종이 텍스트보다 먼저 튀어나오지 않는다.
- `640×360`에서 별도 보조 레이어 없이 2.5바퀴 말림 본체와 중앙 눌림이 식별된다.
- 가죽 띠와 붉은 인장, 정육면체 문양이 게임 카메라에서 구분된다.
- 말림·띠·인장 위에 텍스트와 아이콘이 겹치지 않는다.
- 선택 가능, 선택됨, 보유, 충돌, 사용 완료, 비활성 상태가 기존과 동등 이상으로 구분된다.

##### 8.3 검증 캡처

- 선택 창의 프리셋 3종 동시 표시
- 같은 선택 프리셋이 스톤 트레이에 배치된 전후 비교
- 트레이의 4종 강제 표시 근접 캡처
- `640×360` 픽셀 필터 적용 전·후의 말림 비교
- 선택/충돌/사용 완료 상태 비교

#### 9. 범위 제외 및 보호 항목

- 제공 레퍼런스 이미지를 프로젝트 에셋으로 복사하거나 가공해 사용하지 않는다.
- 증강 아이콘 49종, 증강 효과 로직, 점수 계산, 드래프트 시점과 선택 규칙은 수정하지 않는다.
- 스톤 트레이 모델과 슬롯 수·크기는 변경하지 않는다.
- 텍스트 선명도를 위한 High-Res Screen Overlay 구조는 유지한다.
- 메인 씬은 새 오브젝트를 영구 배치하는 방식으로 수정하지 않고 기존 런타임 생성 구조를 유지한다.
- 기존 5종 구현 문서는 작업 이력으로 보존하고, 이 문서를 후속 디자인 수정의 우선 기준으로 사용한다.

#### 10. 구현 결과 (2026-08-27)

- 상태: `DONE`
- 펼쳐진 오른쪽 종이만 직사각형 카드로 구성하고, 왼쪽 말림 뒤에는 별도의 직사각형 판이 보이지 않도록 재조형했다.
- 왼쪽에는 중앙이 들어간 약 2.5바퀴 말림, 가죽 띠, 정육면체 문양의 붉은 인장을 배치했다. 철 봉과 리본 꼬리는 구현하지 않았다.
- 종이 외곽 손상 4종과 얇은 시안 내부선을 같은 3D 원본에서 프리팹·선택 창 프리뷰로 생성했다.
- 선택 창과 스톤 트레이가 같은 프리셋과 본문 안전 영역을 사용하며, 말림 장식에는 텍스트가 출력되지 않는다.
- 제공된 참조 이미지는 형태와 실루엣 판단에만 사용했으며 프로젝트 에셋으로 복사·가공하지 않았다.
- 검증 결과: 카드 전용 EditMode `24/24`, 전체 EditMode `60/60` 통과. Play Mode에서 양쪽 드래프트 선택과 트레이 배치를 확인했으며 콘솔 오류는 `0`건이었다.
- 후속 수정: Scene 조정값을 공통 기본값으로 이관해 `Pixel Readable Roll Layers`를 제거하고, 말림의 로컬 Z 회전을 `210°`로 고정했다. 원통형 가죽 띠·왁스·인장은 말림 중심 좌표를 공유하며, 밝은 종이색과 슬롯 전체 크기를 적용했다.

### 부록 C. 증강 카드 3D 스크롤 리디자인
> 원래 `docs/augmented_yacht_m7_scroll_redesign_plan.md`였다. `M7-T4`의 구현 계획과 결과다.
#### 1. 목적

현재 절차형 양피지 메시가 원통과 평면을 결합한 형태로 읽히는 문제를 해결하기 위해, 레퍼런스처럼 **일부가 느슨하게 말린 상태에서 본문 종이가 넓게 펼쳐진 정적 3D 스크롤 오브젝트**로 교체한다.

이번 리디자인의 핵심은 다음과 같다.

- 말린 부분과 펼쳐진 부분이 한 장의 종이로 연속되어 보인다.
- 말린 부분 중앙에 실제 두께를 가진 밀랍 인장을 배치한다.
- 종이 섬유, 얼룩, 접힘, 마모를 스타일라이즈드 재질로 명확하게 표현한다.
- 탑다운 카메라에서도 종이 겹침과 뒷면이 읽히도록 형태를 의도적으로 과장한다.
- 카드 정보는 기존 High-Res Screen Overlay를 유지해 3D 픽셀 필터를 우회한다.
- 드래프트와 보유 카드가 같은 5종 스크롤 프리셋을 사용한다.

#### 2. 레퍼런스 해석과 사용 범위

레퍼런스에서 다음 시각 문법만 사용한다.

- 최소 3겹의 단면이 보이는 느슨한 말림
- 말린 종이 아래에서 오른쪽과 아래쪽으로 이어지는 펼쳐진 본체
- 말린 부분을 눌러 고정하는 중앙 밀랍 인장과 짧은 끈
- 불규칙하게 뜯긴 외곽과 얇은 종이 두께
- 가장자리 변색, 넓은 얼룩, 부드러운 접힘으로 구분되는 오래된 종이 재질
- 약한 사선 배치와 접촉 그림자로 생기는 깊이감

레퍼런스의 문구, 인장 문양, 정확한 찢김 위치, 얼룩 배치와 실루엣은 복제하지 않는다. Tessera의 크림슨·골드 장식과 Cozy Fantasy Hearth & Tabletop 아트 방향으로 새로 제작한다.

#### 3. 3D 오브젝트 구성

##### 3.1 기본 구도

- 최종 오브젝트의 평면 점유 크기는 기존 트레이 슬롯 내부 기준 약 `4.30 × 2.30`을 유지한다.
- 펼쳐진 본체가 전체 면적의 `78~84%`를 차지한다.
- 느슨한 롤은 상단 왼쪽에서 중앙 방향으로 뻗으며 전체 너비의 `48~58%`, 높이의 `22~28%`를 사용한다.
- 롤 축은 카드 가로축을 기준으로 `2~5도` 기울여 기계적으로 정렬된 느낌을 피한다.
- 펼쳐진 본체는 완전히 평평하지 않고 중심부는 안정적으로 유지하되 외곽만 `0.03~0.11` 높이 범위에서 들린다.
- 롤과 본체는 별도 원통을 겹치지 않고 하나의 연속된 종이 표면으로 제작한다.
- 롤 단면은 최소 3겹이 보이도록 하며 각 겹의 반지름과 간격을 미세하게 다르게 만든다.

##### 3.2 카메라 가독성용 형태 과장

- 말림 반지름과 높이는 현실 비율보다 약 `1.35~1.55배` 크게 만든다.
- 깊이 방향은 약 `0.78~0.88배`로 압축해 탑다운 화면에서 단면이 지나치게 좁아지지 않게 한다.
- 롤의 안쪽 단면은 메인 카메라 쪽으로 `10~16도` 기울인다.
- 펼쳐진 종이의 아래쪽 두 모서리는 서로 다른 높이로 들고, 중앙 텍스트 영역은 거의 평평하게 유지한다.
- 시각 메시만 과장하며 슬롯 크기와 입력용 콜라이더는 기존 평면 기준을 유지한다.

##### 3.3 밀랍 인장과 끈

- 밀랍 인장은 말린 부분의 길이 기준 중앙 또는 중앙에서 약간 왼쪽에 배치한다.
- 인장 지름은 롤 높이의 `55~65%`, 두께는 종이 두께보다 충분히 크게 만들어 별도 오브젝트로 읽히게 한다.
- 완벽한 원형 대신 12~16각의 불규칙한 가장자리와 눌린 왁스 돌출을 사용한다.
- 인장 아래에는 롤 곡면을 따라가는 얕은 끈 또는 가죽 밴드를 배치한다.
- 짧은 끈 꼬리 한두 가닥이 본체 쪽으로 내려오되 정보 안전 영역을 침범하지 않는다.
- 인장 중심에는 공통 Tessera 문장을 얕게 양각한다. 증강 고유 아이콘은 기존 정보 영역에 유지해 49종 인장 메시 제작을 방지한다.
- 기본 왁스 색은 딥 크림슨 `#8A2725`, 밝은 면은 `#C34B3F`, 깊은 음영은 `#4B1517`을 기준으로 한다.

#### 4. 모델링 사양

##### 4.1 제작 방식

- 런타임마다 메시를 다시 계산하지 않고 에디터 생성기로 구운 정적 메시와 프리팹을 사용한다.
- 하나의 공통 메시 생성 규칙에서 실루엣과 말림을 수정한 5종 메시를 제작한다.
- 5종은 동일한 UV 레이아웃, 재질 슬롯, 피벗, 본문 안전 영역 기준점을 공유한다.
- Unity에는 FBX 또는 검증된 메시 에셋과 프리팹으로 임포트하고 런타임에서는 선택된 프리셋을 인스턴스화한다.
- 씬에 영구 배치하지 않고 기존 트레이 카드 생성 과정에서 프리팹을 로드한다.

##### 4.2 메시 분리

```text
Augment Scroll Root
├─ Paper Front
├─ Paper Underside / Edge
├─ Rolled Inner Layers
├─ Wax Seal
├─ Seal Band
├─ Ribbon Tail
├─ Contact Shadow Plane
└─ Overlay Anchors
   ├─ Bottom Left
   ├─ Bottom Right
   ├─ Top Right
   └─ Top Left
```

- 종이 앞면과 뒷면은 같은 외곽을 공유하되 법선과 재질 값을 분리한다.
- 말린 내부 레이어는 본체와 교차하지 않게 연결하고 겹침 간 최소 간격을 확보한다.
- 종이 측면은 매우 얇지만 화면에서 사라지지 않는 최소 두께를 가진다.
- 접촉 그림자 플레인은 투명 블렌딩을 사용하고 카드 외곽보다 작게 유지한다.
- 오버레이 앵커 4개는 말리지 않는 본문 안전 영역의 모서리에 배치한다.

##### 4.3 폴리곤 예산

| 구성 | 권장 삼각형 수 |
|---|---:|
| 펼쳐진 종이와 외곽 | `1,500~2,400` |
| 롤과 내부 종이층 | `700~1,200` |
| 밀랍 인장과 밴드 | `350~650` |
| 리본과 그림자 | `150~350` |
| 프리셋 1종 합계 | 최대 `4,600` |

동시에 표시되는 보유 카드는 최대 3장이므로, 지나친 세분화 대신 실루엣과 말림 단면에 폴리곤을 집중한다.

#### 5. 종이 및 밀랍 재질

##### 5.1 종이 텍스처 세트

- `Base Color 1024×1024`: 중앙 명암, 넓은 얼룩, 가장자리 변색
- `Normal 512×512`: 낮은 강도의 섬유와 접힘
- `AO 512×512`: 롤 내부, 겹친 단면, 인장 접촉부
- `Roughness 512×512`: 종이 전체는 거칠고 오래 눌린 부분만 약간 매끈하게 구분

종이 질감은 다음 세 단계로 제작한다.

1. **대형 명암**: 중앙은 밝고 외곽은 어두운 완만한 변화와 넓은 얼룩 2~4개
2. **중간 질감**: 구름형 섬유 뭉침, 펼쳐진 접힘과 눌린 자국
3. **미세 질감**: 낮은 대비의 짧은 섬유와 점상 결

권장 색상은 중앙 종이 `#E7CF98`, 따뜻한 얼룩 `#C99B61`, 마른 가장자리 `#8E5030`, 깊은 말림 내부 `#4A2A1B`을 사용한다.

- 종이 Metallic은 `0`, Smoothness는 `0.08~0.14` 범위로 제한한다.
- 롤 내부와 뒷면은 앞면보다 명도 `18~28%`, 채도 `10~18%` 낮게 만든다.
- 강한 범프, 반복 타일, 전 영역의 균일한 사진 노이즈는 사용하지 않는다.
- 접힘은 검은 선 대신 밝은 면과 어두운 면이 짝을 이루는 완만한 법선 변화로 표현한다.

##### 5.2 밀랍 재질

- Metallic은 `0`, Smoothness는 `0.28~0.38`로 종이보다 높게 둔다.
- 가장자리 돌출과 중앙 눌림에만 하이라이트가 생기도록 러프니스 변화를 준다.
- 선택됨 상태는 골드 림 라이트, 충돌 상태는 어두운 균열 데칼, 사용 완료는 채도 감소로 표현한다.

#### 6. 5종 프리셋

모든 프리셋은 동일한 정보 배치, 인장 크기, 재질 슬롯과 콜라이더를 사용한다.

| ID | 명칭 | 메시 차이 |
|---|---|---|
| 0 | 완만한 펼침 | 얕은 롤과 부드러운 하단 굴곡을 가진 기본형 |
| 1 | 찢긴 우측 | 오른쪽 상·하단이 크게 갈라지고 오른쪽 아래가 들림 |
| 2 | 겹친 하단 | 아래쪽 종이가 한 겹 더 드러나고 왼쪽 아래가 접힘 |
| 3 | 비대칭 펼침 | 롤 축이 대각선이고 오른쪽 본체가 더 길게 펼쳐짐 |
| 4 | 낡은 가장자리 | 모서리 마모와 작은 구멍, 가장자리 들림이 가장 강함 |

기존 `OptionCardPresetIds`와 `OwnedCardPresetIds` 배정·상속 로직은 그대로 사용하고 프리셋 ID에 해당하는 3D 프리팹만 교체한다.

#### 7. 카드 정보와 상호작용

- 텍스트, 종류·상태, 아이콘, 설명은 기존 `Pixel Presentation` Screen Space Overlay에서 표시한다.
- 전체 메시 외곽을 사각형으로 투영하지 않고 프리팹의 `Overlay Anchors` 4개를 `WorldToScreenPoint`로 변환한다.
- 정보 영역은 펼쳐진 본체의 오른쪽과 하단 평면에만 배치하고 롤·인장·리본과 겹치지 않는다.
- 드래프트 카드는 같은 3D 오브젝트를 별도 쇼케이스 카메라로 렌더하거나, 프리셋의 정면 렌더 스프라이트를 사용한다. 우선안은 보유 카드와 외형이 정확히 일치하는 3D 렌더 방식이다.
- 화면 그래픽은 모두 `raycastTarget=false`로 유지하고 입력은 기존 고정 `BoxCollider`가 담당한다.
- 호버는 스크롤·인장·리본을 포함한 시각 루트 전체에 `1.0 → 1.06`, 높이 `0.08 → 0.16`, `0.12초 SmoothDamp`를 적용한다.
- 호버된 카드의 오버레이 정렬을 가장 위로 올리고 `LateUpdate`에서 앵커를 투영한다.

#### 8. 구현 순서

1. 프리셋 0의 무재질 블록아웃을 제작해 롤·본문·인장 비율과 트레이 슬롯 점유율을 검증한다.
2. 메인 카메라에서 롤 단면 3겹과 종이 뒷면이 보이도록 형태 과장과 기울기를 조정한다.
3. UV와 공통 종이 재질을 제작하고 대형 명암 → 중간 접힘 → 미세 섬유 순서로 질감을 적용한다.
4. 밀랍 인장, 밴드, 리본과 접촉 그림자를 제작해 롤 중앙에 결합한다.
5. 마스터 메시에서 외곽과 롤 방향을 변형해 나머지 4종 프리셋을 제작한다.
6. Unity 프리팹 5종에 동일한 피벗, 재질 슬롯, 오버레이 앵커를 설정한다.
7. `AugmentTrayCardView`의 절차형 메시 생성 경로를 프리팹 인스턴스 방식으로 교체한다.
8. 드래프트 카드 표현을 3D 쇼케이스 렌더 또는 프리셋 렌더 스프라이트와 연결한다.
9. 기존 프리셋 배정, 랜덤 박스 상속, 호버, 선택, 비활성 동작을 회귀 검증한다.
10. 5종 강제 표시와 보유 카드 3장 캡처로 최종 시각 검수를 진행한다.

#### 9. 테스트 및 완료 기준

- 5종 프리팹이 서로 다른 외곽과 롤 형태를 가지면서 동일한 슬롯 경계 안에 들어온다.
- 각 메시의 정점·삼각형·UV·노멀·탄젠트와 두께가 유효하다.
- 롤 단면에서 최소 3겹의 종이층과 어두운 뒷면이 구분된다.
- 밀랍 인장이 각 프리셋의 롤 중앙 기준점에 배치되고 종이와 교차하지 않는다.
- 종이 중앙, 얼룩, 가장자리, 말림 내부가 최소 네 단계 명도로 구분된다.
- `640×360` 내부 렌더에서도 롤과 인장 실루엣이 하나의 원통 막대로 뭉치지 않는다.
- 정보 오버레이가 롤·인장과 겹치지 않고 네 앵커의 투영 범위 안에 유지된다.
- 화면 그래픽이 레이캐스트를 차단하지 않고 기존 콜라이더 호버·선택이 유지된다.
- 호버 시 3D 오브젝트와 오버레이가 한 프레임 지연 없이 함께 이동한다.
- 프리셋 선택과 랜덤 박스 교체 후 동일한 3D 외형이 보존된다.
- 일반 요트 모드에서는 증강 스크롤 프리팹과 오버레이가 생성되지 않는다.
- 카드 전용 EditMode 및 전체 EditMode 회귀 테스트가 통과한다.

#### 10. 구현 결과

- `AugmentScrollModelFactory`가 펼친 양면 종이, 2중 나선 롤, 인장 밴드, 리본 꼬리, 불규칙 밀랍 인장과 오버레이 앵커를 생성한다.
- `AugmentScrollAssetGenerator`가 위 결과를 `Resources/AugmentScrolls` 아래의 정적 메시·재질·프리팹 5종으로 굽는다.
- 런타임은 프리셋 ID에 맞는 정적 프리팹을 우선 인스턴스화하고, 에셋 누락 시에만 같은 구조를 임시 생성한다.
- 종이 Base Color는 레퍼런스의 오래된 섬유·넓은 얼룩·가장자리 변색을 새로 해석해 제작했으며 URP Lit 재질에 `Metallic 0`, `Smoothness 0.08~0.11`로 연결했다.
- 보유 카드 정보는 펼쳐진 본문 안전 영역의 4개 앵커를 `Pixel Presentation`에 투영하며, 말린 부분과 밀랍 인장을 가리지 않는다.
- 기존 프리셋 배정·상속, 고정 콜라이더 입력, `SmoothDamp` 호버 동작은 유지한다.

##### 10.1 재검증 결과

- 카드·양피지 전용 EditMode 테스트 `23/23`, 전체 EditMode 테스트 `59/59`가 통과했다.
- Play Mode에서 프리셋 `0·2·4`를 사용하는 보유 카드 3장이 각각 정적 메시 5개, 중앙 인장, 화면 오버레이를 생성했다.
- 일반 요트 모드에서는 활성 증강 카드와 오버레이가 모두 0개임을 확인했다.
- 검증 캡처는 `Assets/Screenshots/m7_t4_3d_scroll_validation.png`에 저장했다.
- 기능 기준은 통과했으나 캡처에서 롤이 얇은 직사각 막대처럼 보여 자연스러운 다층 말림 시각 기준은 미통과다. 롤 단면 노출, 본문 연결 곡면, 인장 크기와 명암을 후속 보정한다.

#### 11. 작업 보호와 범위

- 사용자 구현 지시에 따라 모델·재질·프리팹과 런타임 연결을 반영했다.
- 중단된 2D 시안은 프로젝트 에셋으로 사용하지 않는다.
- 현재 프리셋 ID와 게임 상태·난수·선택 인터페이스는 변경하지 않는다.
- 증강 효과 로직과 점수 계산은 수정하지 않는다.
- 메인 씬에 영구 배치하지 않고 런타임 생성 구조를 유지한다.
- `Assets/Scenes/Augmented Dice.unity`는 수정하거나 재저장하지 않는다.
- 레퍼런스의 텍스트, 인장 문장, 구체적인 손상 패턴은 복제하지 않는다.
