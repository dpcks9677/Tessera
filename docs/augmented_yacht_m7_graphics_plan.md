# M7. 증강 시스템 그래픽 요소 추가

## 1. 마일스톤 목적

M5에서는 규칙 검증을 위한 최소 표시와 임시 리소스만 사용했다. M7에서는 모든 증강 그래픽을 실제 게임 품질로 완성한다. 그래픽 요소는 규칙 결과를 표현할 뿐 게임 상태를 직접 변경하지 않는다.

아트 작업은 [`art_style_guide.md`](art_style_guide.md)의 스타일라이즈드 중세 판타지 서재/여관 방향, 앰버·인디고 조명 대비, 크림슨·골드 장식 규칙을 따른다.

### M7 완료 조건

- 55개 증강이 카드 또는 상태 표시만 보고 서로 구분된다.
- 특수 주사위의 논리 종류와 화면 외형이 항상 일치한다.
- 증강 발동의 주체, 대상, 결과를 플레이어가 이해할 수 있다.
- 일반 요트 모드에서는 증강 전용 그래픽과 리소스가 생성되지 않는다.
- 그래픽 연출을 생략하거나 중단해도 게임 논리 상태가 달라지지 않는다.
- [`art_style_guide.md`](art_style_guide.md)와 주요 목표 해상도 기준을 통과한다.
- 사용자 결정에 따라 `M7-T10` 사운드·촉각 피드백은 위 완료 조건에서 제외한다.

## 3. 단계별 사용자 협업 규칙

1. 한 번에 하나의 M7 작업만 현재 단계로 지정한다.
2. 현재 단계라도 사용자가 시작 또는 진행을 언급하기 전에는 `TODO`를 유지한다.
3. 사용자가 작업 ID를 명시하면 해당 작업만 `DOING`으로 바꾼다.
4. 작업 완료 후 현재 작업을 `DONE`으로 바꾸되 다음 작업은 자동으로 시작하거나 `DOING`으로 바꾸지 않는다.
5. 완료 결과를 사용자에게 보고한 뒤 사용자가 다음 작업 ID를 언급할 때까지 대기한다.
6. 작업이 차단되면 `BLOCKED`와 필요한 사용자 결정을 기록하고 다른 단계로 임의 이동하지 않는다.
7. `M7-T10`은 `DEFERRED` 상태로 유지한다. `M7-T9` 완료 후 사용자가 지시하면 `M7-T11`로 이동한다.
8. 각 단계에서 사용자와 확정한 내용은 이 문서의 결정 기록과 작업 로그에 남긴다.

## 4. 확정된 시각 사양

### 4.1 카드와 트레이

> 3D 스크롤 리디자인의 상세 제작·적용 결과는 [`augmented_yacht_m7_scroll_redesign_plan.md`](augmented_yacht_m7_scroll_redesign_plan.md)를 기준으로 한다. 보유 카드는 에디터에서 구운 정적 3D 스크롤 프리팹을 사용하고 누락 시에만 안전한 런타임 폴백을 사용한다.

- 카드 스타일은 석재 트레이와 양피지 카드 조합을 사용한다.
- 드래프트 카드 3장은 화면 중앙의 읽기 쉬운 UI로 표시한다.
- 보유 카드는 3D 석재 트레이에 표시하며 플레이어당 최대 3장으로 제한한다.
- 카드에는 이름, 증강별 아이콘, 한 줄 효과, 종류·상태 배지를 표시하고 상세 설명은 호버 시 별도 영역에 표시한다.
- **텍스트 렌더링 파이프라인 (픽셀 필터 우회)**: 증강 카드의 텍스트가 3D 픽셀화 렌더 타겟을 통과하여 깨지는 문제를 방지하기 위해, 점수표(`ParchmentScoreSheet`) 시스템과 동일하게 3D 트레이 슬롯 좌표를 스크린 오버레이(`Pixel Presentation` Canvas)로 투영하여 선명한 고해상도로 렌더링한다.
- **호버 애니메이션 개선**: 호버링 시 픽셀 격자 튐 없이 부드러운 보간(`Lerp`/`SmoothDamp`)을 통해 카드 고도와 스케일(1.0 → 1.06)이 자연스럽게 늘어나고 안착하도록 구현한다.
- **스크롤(두루마리) 디자인 및 테마 다양화**: 단정한 현대식 네모 카드 형태를 탈피하고, 오돌토돌한 외곽과 실제로 들린 왼쪽 말림, 앤틱 골드 보더를 사용하는 **펼쳐진 양피지 외형 5종**을 구성한다. 드래프트에서 시각 전용 난수로 중복 없이 배정하고 선택한 외형을 보유 카드와 랜덤 박스 교체 결과까지 유지한다.
- 입력은 호버 강조와 클릭 선택까지만 구현하며 드래그 배치는 후속 작업으로 둔다.
- 공통 양피지 프레임에 증강별 아이콘, 색상, 문양을 조합해 활성 증강 45개를 구분한다.
- 삭제된 6개와 의도적으로 미구현한 4개는 드래프트에 넣지 않고 전용 쇼케이스 씬에서 비활성·미사용 사유와 함께 표시한다.
- M7에서는 시각 시스템을 우선 완성하며 프리팹 굽기와 에디터 배치 저장은 후속 작업으로 분리한다.

### 4.2 랜덤 박스

1. `random-box` 증강 카드를 트레이에 놓는다.
2. 해당 카드 위에서 상자가 열리는 이펙트를 출력한다.
3. 결정된 결과 증강 카드를 기존 카드 위에 겹쳐 표시한다.
4. 교체 연출이 끝나면 최종 보유 카드가 최대 3장인 상태로 정리한다.

### 4.3 점수표와 상태

- 변경된 족보 칸은 작은 증강 문양 스티커 또는 인장으로 표시한다.
- 보너스, 잠금, 진행도, 누적 횟수, 성공·실패는 색상과 상태 배지로 구분한다.
- 수동 증강은 사용 가능, 입력 확인, 성공, 실패 이유를 시각적으로 전달한다.

### 4.4 특수 주사위와 VFX

- `weighted-dice`, `golden-die`, `8-sided`, `promotion-die`, `couple-dice`, `sevens-dice`는 타입별 개별 모델을 사용한다.
- 미구현 `strange-die`는 카드용 고유 아이콘과 비활성 표시만 유지하며 M7에서 주사위 모델을 제작하지 않는다.
- 모델과 시각 규칙은 기존 [`augmented-dice`](https://github.com/dpcks9677/augmented-dice) 프로젝트의 구현을 재사용한다.
- 카드 등장, 획득, 발동, 성공, 실패에는 공통 이벤트 이펙트를 사용하고 증강별 차이는 색상, 아이콘, 문양으로 표현한다.
- 사운드와 햅틱은 구현하지 않고 시각 피드백만 M7 범위에 포함한다.

### 4.5 아이콘 그래픽과 픽셀 보정 파이프라인

- 아이콘은 제시된 레퍼런스의 개별 도안을 복제하지 않고 단색 실루엣, 각진 절단, 네거티브 스페이스, 문장형 구도만 시각 문법으로 사용한다.
- 기본 스타일은 **스타일라이즈드 픽셀 문장 아이콘**으로 확정한다.
- 먼저 해상도 독립적인 문장형 원본을 만든 뒤 자동 픽셀 필터를 적용하고, 작은 크기에서 무너지는 외곽과 내부 빈 공간을 수동 보정한다.
- 제작 순서는 `문장형 원본 → 64×64 자동 픽셀화 → 흑백 임계값·제한 팔레트 적용 → 픽셀 수동 보정 → 32·48·64px 검증 → Unity Point 필터 적용`으로 고정한다.
- 자동 픽셀화 결과를 최종본으로 바로 사용하지 않는다. 고립된 1픽셀, 불규칙한 계단, 소실된 틈, 비대칭을 아이콘별로 정리한다.
- 보정 기준은 최소 선 두께 3px, 최소 내부 간격 3px, 대각선 1:1 또는 1:2 계단, 대칭 도안의 좌우 일치다.
- 원본 아이콘은 단색 알파 마스크로 보관하고 카드용 2~4색 픽셀 버전은 같은 원본에서 파생한다. 상태와 VFX 색상은 Unity 틴트로 재사용한다.
- Unity UI용 픽셀 아이콘은 `Filter Mode: Point`, 밉맵 비활성화를 기본값으로 한다. 월드 공간 재사용본은 거리 앨리어싱을 확인해 별도 임포트 설정을 허용한다.
