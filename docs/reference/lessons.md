# 교훈 기록

> **문서 종류**: 작업 규칙 (AI 대상)
> **코드 대조 기준**: 2026-10-24 · 커밋 `d7d59cd`
> 이 문서는 위 시점에 확인된 것만 기술합니다. 계획 항목은 상태 표기로 구분합니다.

사용자가 에이전트의 판단이나 습관을 바로잡은 일을 「실수 / 원인 / 예방 규칙」으로 남기는 문서입니다. 새 세션은 [`process.md`](../plan/process.md) §9 1단계에서 이 문서를 읽고, 같은 실수를 반복하지 않습니다. 매 세션 읽으므로 짧게 유지합니다.

## 어디에 적는가

| 종류 | 적는 곳 |
|---|---|
| 도구 함정·우회로 (다음에도 유효한 기술 사실) | 해당 에이전트 정의 `.claude/agents/*.md` ([`CLAUDE.md`](../../CLAUDE.md) 「영구 지식」) |
| 행동 교정 (사용자가 바로잡은 에이전트의 판단·습관) | 이 문서 |
| 항상 지켜야 할 프로젝트 규칙 | 규칙 원본 문서(`CLAUDE.md`, `AGENTS.md`, `docs/reference/`). 이 문서에는 사례와 원본 위치만 둡니다 |
| 개인 선호·취향 | 사용자 메모리 |

- 규칙 본문은 원본 한 곳에만 둡니다. 이 문서의 「예방 규칙」은 한 줄 요지이고 상세는 「원본」을 따릅니다.
- 한 교정이 둘 이상에 걸리면(예: 도구 함정이면서 행동 교정) 규칙 본문은 원본에, 이 문서에는 사례 한 항목만 둡니다.

## 기록 방법

- **시점**: 교정을 받은 세션 안에서, 다음 작업으로 넘어가기 전에 적습니다. 서브에이전트가 교정을 받으면 오케스트레이터가 적습니다.
- **ID**: `L-nnn` 연번. 번호는 재사용하지 않습니다. 항목을 지우면 아래 「결번」에 적습니다.
- **원인을 모르면** `미확정`이라고 적습니다. 추정으로 채우지 않습니다.
- **정리**: 항목이 20개를 넘으면 원본 규칙으로 완전히 흡수된 항목을 골라 사용자에게 정리를 제안합니다. 임의로 지우지 않습니다.

```markdown
### L-nnn 제목
- 실수: 무엇을 했는가
- 원인: 왜 그렇게 했는가 (모르면 `미확정`)
- 예방 규칙: 다음에는 어떻게 하는가 (한 줄)
- 원본: 규칙 본문이 있는 문서
```

## 항목

### L-001 문서에 실재하지 않는 기능을 적음
- 실수: 존재하지 않는 타입·메서드·씬 이름·메뉴 경로를 문서에 적음
- 원인: `미확정`
- 예방 규칙: 기억이나 추론으로 채우지 않고 확인한 것만 적습니다. 확인하지 못했으면 `미확인`으로 적습니다
- 원본: [`AGENTS.md`](../../AGENTS.md) §2 문서 작성, [`docs/README.md`](../README.md) 「문서 작성 원칙」

### L-002 코드 식별자에 한글을 씀
- 실수: 한글 테스트 메서드명을 씀
- 원인: 기존 테스트 파일의 관행을 따름
- 예방 규칙: 새 식별자는 영문으로 씁니다. 기존 파일이 한글이어도 따라 하지 않습니다
- 원본: [`coding_conventions.md`](coding_conventions.md) 「식별자는 영문으로만 짓는다」, [`AGENTS.md`](../../AGENTS.md) §1 식별자 불릿

### L-003 응답 언어가 한국어에서 벗어남
- 실수: 응답에 한글 깨짐과 일본어가 섞임
- 원인: 컨텍스트에 들어온 중국어 문서와 caveman wenyan 예시를 따라감
- 예방 규칙: 한국어 존댓말로 고정합니다. 컨텍스트 문서의 언어를 따라가지 않고 wenyan 계열을 쓰지 않습니다
- 원본: [`CLAUDE.md`](../../CLAUDE.md) §0, [`orchestration.md`](orchestration.md) 「한국어 출력 고정의 근거」

### L-004 서브에이전트를 작업마다 새로 띄움
- 실수: 같은 역할의 에이전트가 살아 있는데도 작업마다 새로 띄움
- 원인: `미확정`
- 예방 규칙: 새로 띄우기 전에 같은 역할의 살아 있는 에이전트를 먼저 이어 씁니다. 역할별 예외(`tessera-scout`·`tessera-reader`·`tessera-reviewer` 는 매번 새로)는 원본 표를 따릅니다
- 원본: [`CLAUDE.md`](../../CLAUDE.md) 「오케스트레이션」 규칙과 「역할별 재사용 방침」

### L-005 검증 스크린샷을 너무 자주 찍음
- 실수: 촬영 빈도가 늘어 토큰이 크게 늘어남
- 원인: 검증을 반복하는 과정에서 촬영이 기본 동작처럼 굳음
- 예방 규칙: 기본은 찍지 않습니다. 수치로 확인할 수 있으면 조회로 대신하고, 찍더라도 이미지를 읽는 주체는 하나로 모읍니다
- 원본: [`CLAUDE.md`](../../CLAUDE.md) §0.1, [`unity-rest.md`](unity-rest.md) 「스크린샷」

결번: 없음
