# BAL. 증강 밸런스 평가 도구

> **문서 종류**: 트랙 계획 (AI 대상)
> **코드 대조 기준**: 2026-10-24 · 커밋 `a1cb2a6`

## 목표

증강 요트의 세 증강 분류(변형·강화·퀘스트)를 같은 잣대로 재는 평가 기준을 확정하고, 그 기준을 계산해 그래프로 보여 주는 도구를 저장소 `Tools/`에 만듭니다. 밸런스 조정과 새 증강 추가가 계속되므로, 손으로 다시 계산하지 않고 명령 하나로 현행 코드의 수치를 다시 잴 수 있게 하는 것이 목적입니다.

변형의 덮어쓰기(이미 점수가 적힌 대상 칸을 지우고 변형 족보로 바꾼 뒤 추가 턴을 주는 규칙)를 가치 평가에 포함합니다.

Tessera 기본 규칙 변경(`D-057`: Hills 쟁탈 칸, 15턴, 4·9·12라운드 드래프트)과 증강 획득 단계 분류(`D-058`)의 게임 구현도 이 트랙에서 합니다. 도구가 게임 C#을 그대로 컴파일하므로, 바뀐 규칙을 재려면 구현이 먼저입니다.

## 범위

- 포함
  - 평가 기준 문서화 (`docs/reference/augment_balance_analysis.md` 개정)
  - `Tools/` 아래 .NET 콘솔 계산 도구. 게임 C#(`Rules`, `Augments`)을 그대로 컴파일해 씁니다
  - 변형의 시나리오별 지표, 강화·퀘스트 지표
  - 결과 JSON과 정적 HTML 한 장(그래프 포함)
  - 현행 증강 재진단과 `docs/qa/balance/` 기록
  - `tessera-balance-check` 스킬을 도구 출력과 새 기준에 맞춤
  - 게임 구현: 15턴과 단계 드래프트, 증강 턴 규칙 갱신, Hills 규칙, 증강과 Hills의 상호작용, 점수판 UI, 규칙 문서 동기화. 단계 분류는 [`phases.md`](phases.md), 코드 영향 범위는 [`implementation.md`](implementation.md)입니다
- 범위 밖
  - 전체 게임 시뮬레이터. 한 칸 정확 DP 모델을 유지합니다
  - 2인전 승률, 플레이테스트 픽률 (아래 「확정 결정」의 보류 항목)
  - 증강 수치 자체의 조정. 도구는 재기만 하고, 조정은 진단 결과를 보고 별도 태스크로 합니다
  - `step-by-step` 평가. 리워크가 예정돼 있어 `NOT ASSESSED`로 둡니다
  - `duel`, `copycat` 같은 2인 상호작용 증강 (분석 문서 §3.2 한계 5)
  - Unity Editor 연동. 도구는 Editor 밖에서 돕니다

### 발견 (이 트랙 범위 밖, 기록만)

- 상단 보너스 기준 58이 `YachtAugmentRuntime.cs`의 `StepByStepUpperBonusThreshold`와 `StepByStep.cs` 두 곳에 따로 있습니다. 중복 상수입니다.
- 명세 문서 §5의 증강 값은 자연어라 도구가 읽을 수 없습니다. 도구는 코드만 원본으로 삼습니다.
- `step-by-step`은 리워크가 필요하다고 사용자가 판단했습니다(2026-10-24). 리워크를 태스크로 등록할지는 정하지 않았습니다.
