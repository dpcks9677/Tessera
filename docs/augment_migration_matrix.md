# 증강 55개 이식 매트릭스

## 1. 조사 기준선

- 기준 소스: `C:\Users\dpcks\OneDrive\문서\yec\augmented-dice`
- `npm test`: 36개 테스트 파일 통과
- `npm run validate:augments`: 55개 메타데이터 통과
- 데이터 ID는 `1~39`, `41~56`이며 `40`은 존재하지 않는다.
- Unity의 `Assets/StreamingAssets/WebSource/data/augments.json`도 같은 55개 `augmentId`를 가진다.
- 표시 설명과 기존 코드가 충돌하면 사용자 표시 설명을 우선한다. 아래의 “차이/주의”에 예외를 기록한다.

### M6 실행 결과 (2026-08-25)

- **구현 45개**: 드래프트 정의, 개인 런타임 상태, 권위 점수/턴 처리, 최소 수동 행동 UI까지 연결했다.
- **삭제 6개**: 3~8번 안티 계열은 정의·드래프트·랜덤 박스 후보에서 제외했다.
- **의도적 미구현 4개**: `four-by-four`, `two-households`, `strange-die`, `coin-toss`는 사용자 결정에 따라 원본 JSON만 보존하고 실행 풀에서 제외했다.
- 공통 점수 계층은 `기본 족보 점수 → 추진력/더블 다운 강화 → 황금/커플 주사위 보너스` 순서다. 기본 점수가 0이면 최종 보너스와 무관하게 항상 스크래치다.
- `reverse-choice`의 음수 점수는 별도 기입 플래그로 저장해 총점에서 정상 차감한다.
- Unity 검증 기준은 활성 정의 45개이며 원본 메타데이터 55개는 삭제·미구현 근거 보존용으로 유지한다.

## 4. 차이와 주의 사항

- 3~8번 계열인 `anti-ace-deuces`, `anti-four-threes`, `prime-numbers`, `anti-six-fours`, `anti-six-fives`, `anti-five-sixes`는 모두 삭제한다. 구현 목록, 드래프트 선택 풀, `random-box` 후보, 업적·설명 참조에서 제거한다.
- `strange-die`는 설명과 기존 코드가 모두 리워크 대상을 명시하며 현재 드래프트에서 제외된다. M6에서 임의로 기존 동작을 확정하지 않는다.
- `four-by-four`는 기존 가점·감점 포카인드 교체 규칙을 우선 구현하지 않는다. 효과와 밸런스를 다시 검토해 구현 재개를 결정하기 전까지 드래프트 선택 풀에서 제외하고 원본 JSON만 레퍼런스로 보존한다.
- `two-households`는 기존 Full House+Choice 퀘스트를 구현하지 않는다. “풀하우스 두 번”이 직접 체감되는 새 규칙으로 리워크하거나 증강 자체를 삭제하기 전까지 드래프트 선택 풀에서 제외하고 원본 JSON만 레퍼런스로 보존한다.
- `coin-toss`는 기존 동전 3개 결과를 우선 구현하지 않는다. 효과 조합과 밸런스를 다시 검토해 구현 재개를 결정하기 전까지 드래프트 선택 풀에서 제외하고 원본 JSON만 레퍼런스로 보존한다.
- `duel`은 수동 행동안을 폐기하고 획득 라운드 자동 판정으로 되돌린다. 드래프트 및 `random-box` 해결이 양쪽의 첫 굴림 전에 끝나므로 P1·P2 모두 상대 점수를 모르는 상태에서 결투가 활성화된다. 추가 턴도 일반 턴과 동일하게 판정에 포함한다. 양쪽 모두 보유한 경우 승자는 자신의 결투로 +10, 패자는 보상 없음, 동점이면 양쪽 보유자 모두 +5를 받는다.
- 추가 턴은 정규 12턴 밖에서 변형 증강으로 추가된 턴을 구분하기 위한 명칭일 뿐, 규칙상 일반 턴과 동일하다. 라운드를 경과시키고 증강 지속 턴과 퀘스트 제한 턴을 소모하며 프로모션 주사위를 성장시킨다.
- `yacht-bank`는 더 이상 Yacht 족보를 교체하지 않는 보유자 전용 강화 증강이다. 점수 확정 시 킵 존의 가장 왼쪽 주사위 1개만 저축하며, 해당 주사위는 그 턴의 족보 점수 계산에서 완전히 제외한다.
- `random-box`의 상단 보너스 기준 58은 무작위 대체 결과와 별도로 보유자에게 즉시 적용된다. `step-by-step`의 기준 58은 Aces→Sixes 완료 후에만 보유자에게 적용되며, 상단 합계가 58 이상일 때 +55를 확정한다.
- 점수 교체형 대부분은 공통 계산 경로에 구현돼 있지만 전용 경계 테스트가 부족하다. M6에서 각 ID별 정상/실패 사례를 추가한다.
- 기존 `getTurnDuration` 기본값은 45초지만 Tessera 일반 모드는 사용자 결정에 따라 60초로 확정했다.

## 4.1 PC 2인 개인 적용 규칙에 따른 변형 증강 범위

PC 버전의 변형 증강은 기존 기획대로 카드를 획득한 플레이어에게만 적용한다. 한 플레이어가 변형 증강을 선택해도 상대 플레이어의 점수 계산, 족보 이름, 점수 기입 상태에는 영향을 주지 않는다. 기존 권위 코드의 `modificationAugmentIds` 분류 중 `yacht-bank`와 삭제한 3~8번을 제외한 1~24번과 26번이 개인 변형 대상이다. Phase 1 제한은 모든 변형 증강에 적용하지 않고, Yacht 칸을 직접 변형하는 22~24번과 26번에만 적용한다.

기존 드래프트 페이즈는 라운드 1·6·9에서 시작하므로, 여기서 Phase 1은 `currentRound = 1`인 첫 드래프트를 뜻한다.

| 대상 | PC 적용 범위 | 신규 획득 시점 | 추가 주의 |
|---|---|---|---|
| 1~21번 점수/족보 변형 | 획득자 전용 `PlayerRule` | Phase 1~3 모두 가능 | 획득자의 대상 칸이 이미 기입되어 있으면 그 칸만 초기화하고 획득자에게 추가 턴 부여 |
| 3~8번 계열 | 삭제 | 획득 불가 | 선택 풀·랜덤 박스·구현 및 관련 참조에서 제거 |
| 22~24번·26번 Yacht 족보 변형 | 획득자 전용 `PlayerRule` | Phase 1만 | 획득자 자신의 이미 득점된 Yacht 칸 소급 초기화를 피하기 위한 제한 |
| `yacht-bank` | 보유자 전용 `Enhancement` | Phase 1~3 모두 가능 | Yacht 칸을 변경하지 않으며 개인 은행 진행과 증강 보너스만 소유 |
| `fast-straight`, `step-by-step` | 보유자 전용 퀘스트 | 이미 Phase 1 전용 | 개인 변형과 동일하게 플레이어별 상태 소유 |
| `random-box` | 보유자 전용 교체 행동 | 기존 발동 시점 유지 | Phase 2·3 후보에서 22~24번·26번 Yacht 변형만 제외하고, 1~21번과 `yacht-bank`는 보유자 전용 결과로 적용 |
| 37~56번 주사위·행동·퀘스트 | 별도 표기가 없는 한 보유자 전용 | 기존 규칙 유지 | 보유자의 주사위·행동·진행 상태에만 적용 |

이에 따라 M5 이후의 런타임 구조와 검증 지점에 다음 변경이 필요하다.

- 변형 ID는 `globalAugments`가 아니라 각 플레이어의 `playerAugments` 또는 `OwnedIds`에 저장한다. `globalAugments`는 향후 카드 설명이 명시적으로 양쪽 적용을 요구하는 별도 증강에만 사용한다.
- 드래프트 후보·중복·충돌은 보유자 상태를 기준으로 검사한다. 상대끼리는 같은 변형을 보유하거나 동일한 기본 족보를 서로 다른 변형으로 바꿀 수 있다.
- 점수 계산, 점수 미리보기, 족보 이름/설명, 점수 입력 가능 목록, 상단 보너스 합산은 `playerIndex`에 해당하는 변형만 기본 규칙과 합성한다. `prophet`처럼 후보 점수를 참조하는 퀘스트도 해당 보유자의 최종 후보 점수를 사용한다.
- 1~21번 변형은 게임 중간에도 획득할 수 있다. 획득자의 변형 대상 칸이 이미 기입되어 있으면 획득자 점수만 초기화하고 획득자에게 추가 턴 1회를 부여한다. 상대의 동일 칸과 추가 턴 상태는 변경하지 않는다.
- 점수 초기화와 추가 턴 부여는 획득자 개인 상태에 대한 하나의 원자적 결과로 처리한다.
- 점수 초기화 후에는 해당 플레이어의 상단 합계·상단 보너스·총점·승패 비교를 즉시 다시 계산한다. 점수 칸만 비우고 파생 합계를 유지하면 양피지 UI와 권위 상태가 달라진다.
- `double-large-straight`의 상단 기준 60, `random-box`의 기준 58, `step-by-step`의 기준 58과 상단 보너스 +55는 모두 해당 보유자의 점수표와 합산 결과에만 반영한다.
- `random-box`는 Phase 2·3에서도 1~21번 개인 변형과 보유자 전용 강화형 `yacht-bank`를 뽑을 수 있어야 한다. 대신 22~24번·26번 Yacht 변형은 후반 페이즈 후보에서 제외한다. 두 플레이어가 동시에 보유하면 P1→P2 순서로 각각 해결하되, 각 결과의 중복·충돌은 해당 플레이어 보유 목록만 기준으로 검사한다.
- 온라인 상태 스냅샷에는 플레이어별 변형 ID, 적용 순서, 점수 초기화와 추가 턴 상태를 복제한다. 재접속·관전자도 현재 열람 대상 플레이어의 족보 표현을 동일하게 재구성할 수 있어야 한다.

## 4.2 플레이어별 족보 스티커 표시

점수표의 공용 `CATEGORIES` 열에는 기본 족보명을 인쇄된 상태로 유지하고, 변형 증강은 해당 칸 위에 붙는 스티커 오버레이로 표현한다. 한 화면에 양쪽 변형 이름을 모두 펼치지 않고 현재 턴 플레이어의 족보 상태를 기본으로 표시한다.

### 표시 상태와 입력 권한

- P1 턴에는 P1이 보유한 변형 스티커를, P2 턴에는 P2가 보유한 변형 스티커를 표시한다. 변형이 없는 칸은 기본 인쇄명을 그대로 노출한다.
- 실제 턴과 점수 기입 권한을 나타내는 `activePlayerIndex`와 현재 스티커 표시 대상을 나타내는 `viewPlayerIndex`를 분리한다. 기본값은 `viewPlayerIndex = activePlayerIndex`다.
- P1/P2 헤더를 누르면 상대 또는 자신의 족보를 임시로 열람할 수 있다. 열람 전환은 점수 후보, 명령 주체, 점수 기입 권한을 변경하지 않는다.
- 현재 턴과 다른 플레이어를 열람할 때는 `P2 족보 열람 중 · 현재 턴 P1`처럼 두 상태를 함께 표시하고 점수 선택은 실제 턴 플레이어 열에만 허용한다.
- 드래프트 중에는 현재 선택 중인 플레이어의 족보를 표시하고, 게임 종료 시에는 P1/P2 탭 또는 비교 보기를 제공한다.

### 스티커 표현과 전환

- 최초 변형 획득 시에는 스티커가 날아와 대상 족보 위에 붙고 눌리는 강한 획득 연출을 사용한다.
- 일반 턴 전환에서는 반복 피로를 줄이기 위해 약 0.25~0.4초의 짧은 페이드, 잉크 번짐 또는 종이 플립으로 양쪽 스티커 세트를 교체한다. 수동 열람은 더 짧게 전환한다.
- 현재 표시 중인 플레이어 헤더와 점수 열은 밝게 강조하고 반대편 점수 열은 약하게 표시해, 상대 점수가 현재 스티커 규칙으로 얻은 것처럼 보이지 않게 한다.
- 반대편 플레이어도 같은 칸에 다른 변형을 보유했다면 그 점수 칸에 작은 스티커 모서리나 아이콘을 남긴다. 호버 또는 클릭 시 해당 플레이어의 스티커 보기로 전환할 수 있다.
- 긴 변형 이름은 스티커에 맞는 축약명이나 `mark`를 사용하고, 전체 이름·조건·점수식은 호버/클릭 상세 정보로 제공한다.

### 프레젠테이션 데이터와 검증

- 규칙 계층은 `GetCategoryPresentation(playerIndex, category)`와 같은 읽기 전용 결과로 기본 족보명, 변형 표시명, 아이콘, `mark`, 설명을 제공한다. UI는 이 결과를 표시할 뿐 게임 상태를 변경하지 않는다.
- 턴 전환 시 `viewPlayerIndex`가 새 `activePlayerIndex`를 따라가고 모든 대상 스티커가 새 플레이어 기준으로 교체되는지 검증한다.
- 수동 열람 중에도 실제 턴 플레이어의 후보 점수와 점수 기입 권한이 유지되는지 검증한다.
- 두 플레이어가 같은 기본 족보에 서로 다른 변형을 보유한 경우 자동 전환·수동 열람·재접속 후 각각 올바른 스티커가 표시되는지 검증한다.

## 4.3 `step-by-step` 보상 조건 변경안

현재 원본 규칙은 Aces→Sixes 순서 완료 후 상단 보너스를 기본 +35에서 +55로 강화하지만, 상단 합계 63점도 달성해야 실제 +55가 반영된다. 플레이 검토에서 병목은 보상량보다 이 63점 조건으로 확인되었다.

### 조정안 비교

| 안 | 규칙 | 기대 효과 | 위험 |
|---|---|---|---|
| A. 완화형 | 퀘스트 완료 후 `step-by-step` 전용 기준을 63→55로 낮추고, 달성 시 +55 유지 | 기존 보상량·장기 목표를 유지하면서 성공률을 크게 높임 | +55 보너스가 비교적 자주 발생할 수 있음 |
| B. 절충형(선택) | 퀘스트 완료 후 전용 기준을 63→58로 낮추고, 달성 시 +55 유지 | 난이도와 보상 가치를 중간 수준으로 조정 | 여전히 운 나쁜 판에서는 실패 체감이 남을 수 있음 |
| C. 확정 보상형 | 순서 완료 즉시 +55를 지급하고 상단 합계 조건 제거 | 퀘스트 완료 보상이 명확함 | 6개 상단 칸 순서 조건만으로 55점을 보장해 과도하게 강해질 수 있음 |

### B안 적용 결과

사용자 선택에 따라 **B안(63→58 완화, +55 유지)**을 확정한다. `stepRewarded`가 true가 되는 시점에 해당 플레이어의 전용 threshold를 58로 적용하고, 상단 합계가 이미 58 이상이면 즉시 +55 보너스를 확정한다. 58 미만이면 상단 보너스는 지급하지 않으며, 이후 상단 합계가 58 이상이 되는 시점에 확정한다. 순서 실패 시에는 보상과 threshold 완화를 적용하지 않는다.

참고용 단순 모델(각 상단 칸에서 목표 눈이 아닌 주사위를 3회 재굴림, 특수 주사위 제외)에서는 합계 63 이상 확률이 약 4%, 58 이상은 약 11%로 추정된다. 실제 확률은 플레이 전략과 다른 증강 조합에 따라 달라진다.

### 구현·밸런스 주의

- 기본 상단 보너스 +35는 유지하고 `step-by-step` 성공 시에만 +55로 바꾼다. 별도 +20을 추가해 35+20+55가 중첩되는 구조는 피한다.
- `step-by-step`은 보유자 전용 퀘스트이므로 threshold 완화도 플레이어별 상태로 둔다.
- `step-by-step`의 기준 58은 `double-large-straight`(60), `random-box`(58) 등 현재 구현 대상인 다른 상단 기준 변경과 합성해야 한다. 기준을 단순 대입하지 말고 현재 플레이어에게 적용되는 최저 threshold를 유지해, 이후 증강 획득으로 58을 다시 60 이상으로 올리지 않는다. 미구현 `coin-toss`의 기준 57은 합성 대상에서 제외한다.
- +55가 한 번 확정된 뒤 해당 플레이어가 개인 변형을 획득해 상단 칸이 초기화되더라도 이미 지급한 보너스를 회수하지 않는 정책을 우선 검토한다.
- JSON의 reward/description, `stepRewarded` 상태, 상단 보너스 계산, 업적 문구, 저장·회귀 테스트를 함께 갱신한다.
- 순서 실패 시 보상 없음, 상단 합계가 58 미만이면 미달, 순서 완료 시점에 기준을 넘으면 즉시 확정하고 이후 58 도달 시 확정하는 경계 테스트가 필요하다.

현재 사용자 요청으로 확정된 것은 “족보/점수 변형은 획득자에게만 적용하며, Yacht 칸을 변형하는 22~24번과 26번만 Phase 1에서 신규 획득”이라는 원칙이다. `yacht-bank`는 이 범위에서 제외된 보유자 전용 강화 증강이다. 삭제한 3~8번을 제외한 1~21번은 게임 중간에도 등장할 수 있고, 획득자의 대상 칸이 이미 기입되어 있으면 그 칸만 초기화한 뒤 획득자에게 추가 턴을 준다. 이 초기화와 추가 턴은 게임의 핵심 콘텐츠로 유지한다. M6에서는 현재 전역으로 구현된 대표 증강을 개인 적용으로 전환하고 다음 정책을 검증한다.

1. 구현 대상인 1~21번 변형이 대상 칸을 초기화하면 획득자에게만 추가 턴 1회를 예약한다.
2. `yacht-bank`는 양쪽이 공유하지 않으며 보유자의 개인 진행 상태와 증강 보너스로 처리한다.
3. 변형 중복·충돌은 플레이어별로 검사하며 상대끼리는 같은 변형 또는 같은 대상의 서로 다른 변형을 보유할 수 있다.
4. `8-sided` 등 주사위 구성 변경은 보유자 전용으로 둔다.
5. 복수 `random-box`는 P1→P2 순서로 각각 해결하고 각 보유자의 중복·충돌만 자신의 후보에서 제외한다.
6. `random-box`가 직접 바꾸는 상단 보너스 기준 58은 보유자 전용으로 둔다.

## 4.4 `yacht-bank` 강화형 확정 명세

#### 규칙과 판정

- 획득 후 보유자의 다음 3턴 동안 활성화한다. 추가 턴도 일반 턴과 동일하게 남은 횟수를 소모한다.
- 각 활성 턴의 점수 확정 시점에 `IsKept == true`인 주사위 중 킵 슬롯 인덱스가 가장 작은 주사위 1개를 저축 대상으로 확정한다. 기입 전에 언킵하거나 재배치해 왼쪽 주사위가 바뀌면 최종 배치를 따른다.
- 저축 대상 주사위는 눈금만 차감하는 것이 아니라 해당 턴의 족보 판정과 점수 계산에서 완전히 제외한다. 나머지 주사위만으로 기존 족보를 계산한다.
- 킵 존이 비어 있으면 0점을 저축하되 해당 턴 1회는 소모한다. 추가 턴과 시간 초과로 기입된 턴도 같은 규칙을 적용한다.
- 저축액은 대상 주사위의 눈만큼 증가하며 누적 상한은 15점이다. 상한에 먼저 도달해도 세 번째 일반 턴이 끝날 때까지 효과를 유지한다.
- 세 번째 저축이 끝난 다음 보유자의 턴 시작에 누적액을 `augmentBonusScore`로 지급하고 완료 상태로 전환한다. 그 턴이 추가 턴이어도 지급 시점으로 인정한다.
- Yacht를 포함한 기존 점수표 족보의 이름·슬롯·기입 상태는 변경하거나 초기화하지 않는다. 따라서 전역 변형 목록과 Phase 1 전용 후보군에 포함하지 않는다.

#### 권위 상태와 동기화

- 요트 뱅크 진행 상태는 보유자별로 `remainingTurns`, `balance`, `paidOut`을 소유한다.
- “가장 왼쪽” 판정은 화면 좌표가 아니라 권위 상태의 킵 슬롯 인덱스를 기준으로 한다. `YachtDieState`에 `KeepSlotIndex` 같은 필드를 두고 킵 시 가장 왼쪽 빈 슬롯을 권위 계층이 배정한다.
- 프레젠테이션 전용 `keptSlotIndices`만으로 저축 대상을 정하지 않는다. 로컬·온라인·재접속 상태에서 동일한 주사위가 선택되어야 한다.
- 킵 상태가 바뀌면 저축 대상과 남은 주사위의 점수 후보가 함께 달라지므로 즉시 점수 미리보기를 다시 계산한다.

#### 킵 존 연출

- 효과가 지속되는 동안 킵 존의 가장 오른쪽 구역을 은행 저장소로 사용하고 앤틱 골드 `#e5a93c` 계열로 발광시킨다. 이 구역은 저축 대상 슬롯이 아니라 효과 상태를 나타내는 시각 요소다.
- 공유 보드에서 상대 효과로 오인하지 않도록 보유자의 활성 턴에는 정상 강도로 발광하고 상대 턴에는 끄거나 약하게 표시한다.
- 점수 확정 시 왼쪽 저축 대상 주사위에서 오른쪽 금색 은행 구역으로 빛이 이동하고, 도착 시 구역을 짧게 점멸시키며 `+눈금`과 `누적/15`를 표시한다.
- 세 번째 저축 뒤에는 지급 대기 상태를 표현하고, 다음 보유자 턴 시작에 지급 펄스를 재생한 뒤 발광을 종료한다.

#### 필수 회귀 테스트

- 킵 슬롯이 여러 개일 때 가장 작은 슬롯 인덱스의 주사위만 저축한다.
- 왼쪽 주사위를 언킵하면 다음 왼쪽 주사위가 대상으로 바뀌며, 킵 존이 비면 0점을 저축한다.
- 저축 대상 한 개만 족보 계산에서 제외되고 나머지 킵 주사위는 정상적으로 계산된다.
- 보유자 턴 3회, 15점 상한, 다음 보유자 턴 지급 및 `augmentBonusScore` 합산을 검증한다.
- 추가 턴은 진행 횟수를 소모하고, 상대 턴은 진행 횟수를 소모하지 않으며 상대의 점수 계산에도 영향을 주지 않는지 검증한다.
- Yacht 족보가 기본 이름·50점 규칙·기입 상태를 유지하고 Phase 2·3 획득도 정상 동작한다.

## 4.5 공통 점수 계층과 강화 표시

갬빗·추진력·더블 다운은 황금 주사위·커플 주사위처럼 별도로 발생한 주사위 보너스 점수를 강화하지 않는다. 점수 계산 과정에서 기본 족보 점수, 강화된 기본 점수, 주사위 보너스, 최종 기입 점수를 분리한다.

### 점수 계산 순서

1. 갬빗이 활성화된 경우 해당 단계의 4개 또는 6개 일반 주사위를 점수 계산 입력으로 구성한다.
2. 입력 주사위로 `baseCategoryScore`를 계산한다. 이 값에는 황금·커플 주사위 등에서 발생하는 고정 추가 점수를 포함하지 않는다.
3. 추진력 또는 더블 다운이 활성 상태이고 `baseCategoryScore > 0`이면 배율을 적용해 `enhancedCategoryScore`를 계산한다. 단독 적용은 `floor(baseCategoryScore * 1.5)`, 둘이 함께 적용되면 중첩 곱셈 대신 `floor(baseCategoryScore * 2.0)`을 사용한다. 배율이 없으면 갬빗 4·6주사위 결과를 포함한 기본 족보 점수를 그대로 사용한다.
4. 황금·커플 주사위 등으로 발생한 `diceBonusScore`를 별도로 계산한다.
5. `finalCommittedScore = enhancedCategoryScore + diceBonusScore` 순서로 합산해 점수표에 기입한다.

스크래치는 `finalCommittedScore`가 아니라 `baseCategoryScore == 0`으로 항상 판정한다. 따라서 기본 족보가 0점이고 주사위 보너스만 붙어 최종 점수가 양수가 된 경우에도 스크래치이며 추진력을 준비시키고, 현상금 사냥꾼의 스크래치 수에도 포함된다. 다음 턴의 기본 족보 점수가 양수일 때 그 기본 점수만 강화하고 주사위 보너스는 증폭하지 않는다. `doubling`, `copycat`, `prophet`처럼 동일 점수를 비교하는 퀘스트도 `baseCategoryScore`를 기준으로 하며 주사위 보너스와 증강 보너스는 비교에서 제외한다. 상단 족보에 붙은 주사위 보너스는 최종 기입 점수에 포함된 뒤 기존 규칙대로 해당 플레이어의 상단 합계에도 포함한다.

`reverse-choice`의 `baseCategoryScore = 30 - sum(dice)`는 음수가 될 수 있다. 음수 값을 그대로 저장하고 총점 합산에서 차감해야 하며, 총점 계산이 양수 점수만 더하는 방식이어서는 안 된다.

갬빗의 가변 주사위 판정은 기존 계산 방식을 따른다. 상단 족보와 Choice는 모든 입력 주사위를 사용하고, Four of a Kind는 같은 눈 4개 이상이면 성립해 전체 합을 사용한다. Full House는 같은 눈 3개 이상과 다른 눈 2개 이상, Yacht는 같은 눈 5개 이상으로 성립하며, Straight는 필요한 연속 눈이 입력에 포함되었는지 판정한다.

### 점수 결과와 권위 메타데이터

- 점수 미리보기와 확정 결과는 최소한 `baseCategoryScore`, `enhancedCategoryScore`, `diceBonusScore`, `finalCommittedScore`를 구분해 전달한다.
- 점수 칸에는 추진력 또는 더블 다운이 실제 적용된 경우 해당 `ScoreEnhancementSource`를 저장한다. 함께 적용되면 두 출처를 모두 복원할 수 있어야 한다.
- 갬빗은 주사위 개수 변화로 기본 족보 점수를 구성하는 효과이므로 4주사위 페널티와 6주사위 보상 모두 강화 출처를 기록하지 않고 글로우를 표시하지 않는다.
- 주사위 보너스만 추가된 점수에는 강화 출처를 기록하지 않으며 글로우도 표시하지 않는다.
- 점수 이벤트와 온라인 스냅샷에도 강화 출처를 포함해 UI 갱신, 재접속, 관전자 화면에서 같은 표현을 복원한다.

### 강화 점수표 글로우 연출

- 추진력 또는 더블 다운으로 기본 족보 점수가 강화된 점수를 기입할 때 기존 점수 폰트, 크기, 굵기와 기본 색상은 변경하지 않는다. 갬빗으로 얻은 점수는 4·6주사위 턴 모두 별도 효과 없이 기존 폰트로 출력한다.
- 기존 글자 외곽에 앤틱 골드 `#e5a93c` 계열 글로우를 적용하고, 기입 순간에는 약 0.4~0.7초 동안 한 번 강하게 펄스한 뒤 낮은 강도의 상시 글로우를 유지한다.
- 글로우는 최종 숫자 전체에 적용하되 툴팁 또는 상세 정보에서는 `기본 점수`, `적용된 강화와 배율`, `주사위 보너스`, `최종 점수`를 각각 확인할 수 있게 한다.
- 점수표를 다른 플레이어 기준으로 전환하거나 다시 그려도 저장된 `ScoreEnhancementSource`를 기준으로 글로우를 복원한다.

### 필수 회귀 테스트

- 기본 0점에 황금·커플 보너스만 붙은 턴이 추진력을 준비시키는지 검증한다.
- 추진력이 기본 양수 점수만 1.5배하고 주사위 보너스를 원값 그대로 마지막에 더하는지 검증한다.
- 더블 다운 단독은 기본 점수만 1.5배하고 추진력과 동시 적용 시 기본 점수만 2배하며, 기본 점수 0이면 최종 점수가 양수여도 스크래치인지 검증한다.
- `doubling`, `copycat`, `prophet`, `bounty-hunter`가 기본 족보 점수를 기준으로 판정하는지 검증한다.
- `reverse-choice`의 음수 점수가 저장·복제되고 총점에서 정상적으로 차감되는지 검증한다.
- 갬빗 4·6주사위의 기본 족보 계산과 주사위 보너스 계층이 분리되는지 검증한다.
- 갬빗 4주사위 페널티와 6주사위 보상 점수가 모두 기존 폰트로 출력되고 강화 출처나 글로우를 갖지 않는지 검증한다.
- 주사위 보너스만 있는 점수에는 글로우가 없고, 갬빗 6주사위와 추진력이 함께 적용된 경우에는 추진력 출처와 글로우만 기록되는지 검증한다.
- 저장·복제·재접속 및 P1/P2 족보 보기 전환 후에도 강화 글로우가 동일하게 복원되는지 검증한다.

## 4.6 추가 턴 공통 규칙

추가 턴은 정규 12턴 밖에서 변형 증강으로 인해 생긴 턴을 구분하는 명칭이다. 규칙 처리에서는 일반 턴과 완전히 동일하게 취급한다.

- 추가 턴도 정규 턴과 같은 `advanceTurn` 경로를 사용해 라운드와 해당 플레이어의 턴 진행 상태를 정상적으로 경과시킨다.
- 턴 단위 증강의 남은 지속 횟수를 1 감소시킨다. `yacht-bank`의 3턴 저축도 추가 턴에 진행된다.
- 퀘스트의 시작 턴·제한 턴·연속 턴 판정에 포함한다. `holdout`은 정규 12턴 이후의 추가 턴에도 달성할 수 있다.
- 내 추가 턴 시작에도 `promotion-die`를 성장시킨다.
- 결투가 활성화된 범위에서 발생한 추가 턴 점수도 일반 턴 점수와 동일하게 판정한다.
- 턴 시작·굴림·점수 기입·턴 종료 이벤트와 온라인 복제 형식은 정규 턴과 같은 경로를 사용하고, UI 표기용 `isExtraTurn`만 별도 메타데이터로 유지한다.

## 4.7 프로모션·세븐스 다이스 확정 규칙

### 프로모션 주사위

- 획득 즉시 대상 주사위의 눈을 1로 설정한다.
- 획득한 턴에는 성장시키지 않는다.
- 이후 보유자의 턴이 시작될 때마다 눈을 1 증가시킨다. 그 턴이 추가 턴이어도 성장한다.
- 눈은 6을 초과하지 않는다. 눈 6 상태로 족보를 기입하면 효과를 완료하고 해당 주사위를 일반 주사위로 변경한다.
- 성장 처리는 턴 종료가 아니라 보유자 턴 시작 이벤트 한 곳에서만 수행해 중복 증가를 방지한다.

### 세븐스 다이스

- 눈 7은 Choice·Four of a Kind·Full House·Yacht의 동일 눈 판정에서 일반 숫자와 똑같이 사용한다.
- Small Straight에는 `4-5-6-7`, Large Straight에는 `3-4-5-6-7`을 추가한다.
- 별도의 상단 `Sevens` 족보 칸은 만들지 않는다.
- 위 확장 원칙은 기본 족보뿐 아니라 변형 증강의 점수 계산에도 적용한다.

#### 변형 족보 우선순위

1. 변형 증강은 대상 칸의 기본 족보 조건을 완전히 교체한다.
2. 눈 7은 교체된 변형 족보의 조건 안에서 일반 숫자로 사용한다.
3. 변형 카드가 허용 눈, 금지 눈, 고정 배열을 명시하면 해당 카드 조건이 세븐스의 일반 확장보다 우선한다.
4. 변형 카드가 기본 Straight 조건을 직접 사용하는 경우에만 세븐스의 확장 Straight를 적용한다.

#### 눈 7로 확장되는 변형

- `three-of-a-kind`: 눈 7도 같은 눈 3개 판정에 사용한다. 현재 세븐스 주사위가 2개라 7 세 개는 나올 수 없지만 판정기는 향후 주사위 구성 확장을 고려해 허용한다.
- `two-pair`: 눈 7 두 개를 한 페어로 인정하고, 포카드 인정 규칙도 눈 7에 동일하게 적용한다.
- `head-and-tail`: 연속 눈에 `5-6-7`을 인정하고 눈 7도 페어 구성에 사용할 수 있다.
- `double-large-straight`: 변형된 Small Straight 칸에서도 `3-4-5-6-7`을 Large Straight로 인정한다.
- `duplex-house`: 차이가 1인 `6·7` 조합도 인정해 `6-6-6-7-7`과 그 역구성을 허용한다.

#### 카드 설명에서 눈 7을 허용하는 변형

- `odds`: 눈 7을 홀수로 인정한다.
- `prime-collection`: 눈 7을 소수로 인정하되 2·3·5가 각각 최소 1개 포함되어야 한다.
- `high-dice`: 눈 7을 허용 숫자와 합계에 그대로 사용한다.

#### 카드 설명이 눈 7 사용을 막는 변형

- `tiny-house`: 5·6·7 금지 조건이 우선하므로 눈 7이 하나라도 있으면 실패한다.
- `evens`: 눈 7은 홀수이므로 실패한다.
- `mountain`: 정확히 `2-3-4-5-6`이어야 하므로 눈 7로 다른 눈을 대체할 수 없다.
- `fibonacci-numbers`: 정확히 `1-1-2-3-5`이어야 하므로 눈 7을 사용할 수 없다.

#### 합계형 변형

- `lucky-sevens`, `perfect-squares`, `gambler`, `2nd-choice`, `reverse-choice`, `blackjack-21`은 눈 7을 다른 눈과 동일하게 주사위 합계에 포함한다.
- `reverse-choice`는 눈 7로 합계가 30을 초과하면 확정된 음수 점수 규칙을 그대로 적용한다.

#### 구현·회귀 요구사항

- 증강 요트 계산기는 눈 1~7을 받을 수 있어야 하며, 기본 요트 계산기의 1~6 전용 제약을 전역으로 완화하지 않고 세븐스 보유자의 합성 규칙에서 확장한다.
- Small Straight `4-5-6-7`, Large Straight `3-4-5-6-7`과 `double-large-straight`의 확장 Large Straight를 각각 검증한다.
- 허용형, 금지형, 고정 배열형, 합계형 변형마다 눈 7이 포함된 성공·실패 경계 사례를 추가한다.
- 현재 두 개뿐인 세븐스 주사위로 불가능한 7 포카드·7 Yacht·7 트리플은 런타임 후보에서 자연스럽게 발생하지 않지만 계산기 단위 테스트에서는 값 영역 규칙으로 허용한다.
